# Reduce complete Terminal Bench supervisor tokens

The [implementation plan](../external/ipfs_accelerate/docs/agent_supervisor/terminal_token_metadata_plan.md)
retains general planning and `llm_router`. It assigns DuckDB to current evidence
indexes, Quack to qualified bounded owner reads, DuckLake to observational history,
formal systems to fresh accepted receipts and residual obligations, and semantic
capsules to the current evidence the model needs. The available autoencoders and
embeddings can rank nominations; similarity does not establish proof or authorize
omission.

The first implementation adds the explicit `common-bindings@1` coding metadata
view on original semantic transport `@1`. Shared schema/version/source metadata
stays inline, source bodies and verdicts remain available, and exact restoration
is checked. Selection compares both complete coding inputs with unchanged
workspace, Doctor/public instruction and reply instruction. It selects the
candidate only when strictly smaller in bytes and the named byte-derived proxy;
otherwise it retains the original and records fallback.

The audit child independently reconstructs the selected input and its ordinary
reply contract, retaining the undelivered original contract separately. The
native catalog bridge pins an owner-prepared artifact and independently supplied
source/task/revision/evidence population before actual native registration.
Catalog nominations cannot authorize model use. Active Quack transport and a
DuckLake extension deployment remain separate qualifications.

The [qualification record](../external/ipfs_accelerate/docs/agent_supervisor/evidence/terminal-token-metadata-20261007/README.md)
binds exact source/test hashes, independent review and retained development
failures. The combined fresh-seal suite passed **354 tests**, with zero failures,
errors or skips. After integration, all 56 focused runner/dispatch/audit checks
passed under a new seal, and all four local documentation gates passed again.
These focused checks overlap the combined suite. Concurrent
lifecycle cleanup work was integrated without changing any reviewed metadata
source, new test or archive-policy helper body.

Four authored one-file fixtures establish the complete-input selection boundary:
one capsule expands and falls back; three, eight and 22 capsules shrink. They do
not establish the actual two-path benchmark population, actual provider tokens,
rewards or savings. No live provider or Terminal Bench run was launched for this
qualification. Temporary seal databases and test catalogs remain local.

The prior qualified compact-transport comparison used **327,117 total tokens**
against **246,992 baseline**, a 32.44% increase despite a smaller initial input.
That adverse result remains recorded. The next step is an owner-emitted metadata
census of the actual prepared coding view, then a separately versioned matched
trial varying only this representation. Count all retained planning, coding,
lookup, continuation and repair costs; preserve missing usage as unknown and
avoid double-counting cached input, reasoning output and cumulative records.
Fresh formal status reuse, bounded expansion and checked history deltas follow
as separate measured treatments. Total token savings remain unmeasured.
