# Independent CodebaseIR qualification lanes

These tools advance lanes 1, 2 and 3 from the repository CodebaseIR roadmap.
They live outside the actively edited datasets and supervisor packages. Each
lane owns its own implementation, tests and command-line interface.

| Directory | Deliverable | Roadmap tasks |
| --- | --- | --- |
| [acceptance](acceptance/README.md) | Multi-unit fixtures, retained admission/worker checks, advisory-stage integrity and failed-attempt accounting | RPI-012/016/018/019/020/023/028 |
| [corpus_audit](corpus_audit/README.md) | Source and split audits, retained cohort inventories, frozen final protocols and offline prediction scoring | RPI-008/011/020/027/028 |
| [release_audit](release_audit/README.md) | Dependency closures, historical snapshots, commit-pinned acceptance reconciliation and scoped release inclusion | Phase 0; RPI-001/003/019 |

Run the three independent test suites and a fixture-to-auditor control:

```sh
python3 qualification/codebase_ir/run_qualification.py
```

Run the three offline workflows with explicitly pinned manifests:

```sh
python3 qualification/codebase_ir/run_qualification.py \
  --advisory-evidence-manifest /absolute/path/advisory-input.json \
  --final-evaluation-manifest /absolute/path/final-input.json \
  --release-matrix-manifest /absolute/path/release-input.json
```

The advisory workflow checks selected retained stages and attempted work, keeping
completed stages separate from an attempt's overall result. The final workflow
freezes authored evaluation fixtures and scores existing prediction exports;
authored demonstration outputs do not establish numerical model quality. The
release workflow reconciles every acceptance row against immutable Git commits,
its frozen criterion and selected evidence. A valid report can contain failed
attempts, rejected predictions, criterion drift or unavailable evidence.

Each spec is copied byte-for-byte before its lane runs. The runner requires the
report to reference that exact SHA-256, verify unchanged inputs and explicitly
deny current authority, training and native qualification execution. It also
requires the lane-specific limits on full-join qualification, model selection,
promotion and production acceptance requalification. All outputs remain scoped
offline evidence; the released ledger's declared closures stay separate from
this package's qualification results.
The final-evaluation bundle uses relative paths, so that lane receives its
original manifest location. The retained copy binds the required bytes, and
the original manifest is rechecked after its workflow and at combined completion.

The auxiliary-body supplement verifies explicitly selected retained invocation,
inference and metrics records against their original advisory anchors. It
provides structural joins while numerical replay and signature authentication
remain unverified. FINAL locks keep protocol, cohort, targets and source bytes
fixed across later prediction exports. The lock's raw SHA256 must be supplied
explicitly; its original location and exact bytes are checked after scoring and
again before the combined result is published. A new lock generated by this
runner remains separate from the preexisting lock requested for scoring.

Portable release verification reads the original bundle manifest location so
its relative content paths retain their meaning. It binds that exact manifest
hash and rechecks selected evidence, Git object paths and source comparison
dispositions without relying on original repository paths. Missing or changed
source files remain recorded review findings; selected-byte portability does
not establish runtime dependency closure or production acceptance.

Use `--retained-join-manifest <capture-spec.json>` for a selected native corpus

and primary pin-manifest bytes, plus an explicit original-to-retained root
mapping. The workflow captures supported checkpoint/context/lineage records,

To prepare or review a proposed response to existing corpus closure requests,
use `--closure-response-requests <closure_requests.json>` and optionally
`--closure-response <proposed-response.json>`. The request's adjacent captured
inputs and owner facts are retained by the lane. A well-formed review can still
find contradictions, leakage or incomplete evidence. Responses never implicitly
change the native completeness flags.
Add `--closure-cohort-inventory` to enumerate every connected group, including
singletons, in that generated review. The inventory retains source identities,
roles, native target memberships, ancestry exposure, relationship evidence and
unresolved claims. It requires exact hashes for the review's adjacent captured
artifacts. An inventory with no observed split connections still leaves
independence and native closure certification unverified.

The runner copies these implementations to a private directory under
`artifacts/codebase_ir_parallel_qualification/`, runs suites in separate processes
with one numerical thread, and retains logs, hashes and `results.json`. The
cross-lane checks exercise both a deliberately leaky cohort and an independent
four-role cohort. `--output` accepts a new output directory and refuses an
existing path. Test execution has a timeout and terminates its child process
group if the deadline expires. Use repeated `--evidence-report <report.json>`
arguments to retain hashes and copies of separate native or release audit runs
without repeating their execution.
Report inputs must be stable bounded regular JSON objects. Duplicate fields,
non-finite numbers, final-component symlinks and special files are refused.

The acceptance ledger records expected behavior for the receiving repository
pipeline. Its source checks and result validator do not issue checker evidence
or signed admission. The corpus auditor reports uncertainty when dependency or
ancestry coverage is incomplete. The release auditor preserves dynamic/optional
import frontiers and missing runtime dependencies in its report.

These tools do not execute production admission, the actual worker
edit/successor cycle, model fitting, promotion or shared-owner publication. They
provide fixtures and diagnostics for those owners; passing their unit tests does
not close the roadmap's production acceptance tasks.

Use immutable exports and private temporary databases when extending a lane.
Avoid changing the shared roadmap, runtime registry, selected model heads or
source-owner files as part of this qualification package.
