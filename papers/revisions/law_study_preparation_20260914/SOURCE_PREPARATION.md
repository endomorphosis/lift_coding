The current package contains 30 proposed source families and 60 concrete paired
task/oracle specifications. All have actual retained source bodies. None is
scientifically admitted, assigned to a final split, or executed by a model.
`candidate_cohort_coverage.json` is a source-integrity and draft-count report;
its PASS status does not qualify the full study.

The prospective source rule is `prospective_eligibility_rule.json`.
`legal_cve_proposal_v2/` is the current legal/CVE draft. The earlier v1 remains
preserved because an ordered review identified earlier operative legal
sections. `legal_selection_v2.json` records the correction and the explicit
source-screen decisions. No model outcomes informed either draft. The rule's
complete deterministic screen, alternative-row handling, semantic adaptation,
fork/rename closure and near-neighbor audit still require independent review
before selection or release; this is not a claim that every possible earlier
source has been shown unusable.

`cve_screening_audit.json` records every metadata row through the last proposed
CVE candidate: 25 historical-repository exclusions, 206 nonpreferred-language
rows, four inspected source failures, twelve proposed sources, and fifteen
same-repository non-independent rows. The five alternative Python rows from
unqualified repositories are now screened as same-family rather than left
open; they are not independent families and do not replace the twelve drafts.
Fork/rename/near-neighbor closure still blocks scientific admission.

Ten CVE repositories have exact-commit root license files retained and
classified in `license_inventory_v1.json`. The setroubleshoot primary file also
contains an explicit GPL-2-or-later header, although no root license was
recovered; the exact-commit dependency/source license inventory still needs
completion. Trape still has no recognized retained license file: its exact-commit
README asserts CC-BY-3.0 for project content and MIT for formatting/display
source, but no LICENSE/COPYING blob or MIT grant text is retained and `core/db.py`
is not unambiguously covered. Five of the thirty recovered files fail Python 3
AST parsing (two Salt, two IBus, one Trape); one caller file was recovered
without an AST status. AST parsing is not an execution or security qualification.

The SkillCenter package is `skill_candidates_v1/`. Its readable `skill-new-*`
identifiers are preparation labels. The coverage report maps them to the
original canonical repository-derived `family:<sha256>` lineage identities;
the final scheduler must use those lineage bindings. Exact old-family keys
and cross-population repository overlaps are excluded. Full fork/alias and
shared-source closure remains necessary before claiming independence.

The useful next implementation is to turn these specifications into qualified
fixture construction, independent observation/oracle code and adequate native
handler interfaces, then test permitted effects, forbidden effects and failed
candidate repair using constructed development controls. The current LA-030
straight-line two-sink profile is insufficient for the specified computation,
SQLite, archive, template, route/state and fixed-program operations. A model
must generate the actual task program within a reviewed richer profile; a
handler that silently solves the task for a fixed forwarding program would
not establish generated-program task completion.

Model admission still requires exact per-call preflight/response prompt-token
agreement, the complete 120-second attempt deadline, retained diagnostic
operation/path/errno for the old watchdog observation problem, and durable
schedule/ownership/resume qualification. Warm service reuse has a 10,000-second
total service bound and a separate 360-second startup-readiness bound. LA-032
must freeze the original 900 identities before the thirty bounded family-batch
tasks run; these preparation artifacts do not complete LA-032 or LA-031.
