# Add ASP.NET Core security headers with Lib.AspNetCore.Security

## Background
Lib.AspNetCore.Security is a library for ASP.NET Core that provides security features such as Content Security Policy (CSP), Strict Transport Security (HSTS), and Expect-CT.

## Use Cases
- Add a Content Security Policy (CSP) to reduce XSS risk.
- Enforce HTTPS with Strict Transport Security (HSTS).
- Add Expect-CT to prepare for/monitor Certificate Transparency policy enforcement.

## Inputs
- An existing ASP.NET Core application.
- NuGet package choice:
  - Lib.AspNetCore.Security
  - Lib.AspNetCore.Mvc.Security

## Outputs
- Security-related HTTP response headers added by the application (for example: CSP, HSTS, Expect-CT), depending on how you configure the library.

## Steps
1. Open your ASP.NET Core solution.
2. Choose the package(s) you need:
   - Use `Lib.AspNetCore.Security` for general ASP.NET Core usage.
   - Use `Lib.AspNetCore.Mvc.Security` if you need the MVC-related features.
3. Install `Lib.AspNetCore.Security` from NuGet:
   - In Package Manager Console:
     - `Install-Package Lib.AspNetCore.Security`
4. (Optional) Install `Lib.AspNetCore.Mvc.Security` from NuGet:
   - In Package Manager Console:
     - `Install-Package Lib.AspNetCore.Mvc.Security`
5. Open the library documentation and select the feature(s) you want to enable (CSP, HSTS, Expect-CT): <URL>
6. Apply the documented configuration to your application (for example, add the appropriate middleware and/or MVC integration per the docs).
7. Build the application.
8. Run the application locally.
9. Make an HTTP request to a page/endpoint that should return the headers.
10. Inspect response headers to confirm the expected security headers are present.

## Verification
Run your app, then verify headers appear in responses.

```bash
# Replace URL with an endpoint in your app
URL="http://localhost:5000/"

# Fetch response headers
curl -sSI "$URL" > /tmp/headers.txt

# Show any security-related headers that are commonly set by this library's features
grep -Ei '^(content-security-policy|strict-transport-security|expect-ct):' /tmp/headers.txt || true

# Expected outcome:
# - At least one of these headers is printed if you've enabled the corresponding feature(s)
#   (Content-Security-Policy, Strict-Transport-Security, and/or Expect-CT).
```

## Safety
- Roll out CSP carefully: overly strict policies can break site functionality; validate in a safe environment before production.
- HSTS can lock clients into HTTPS for your domain; ensure HTTPS is correctly configured before enabling.
- Expect-CT behavior and browser support/policy can change; verify current needs and impact for your environment.
