# Securely Integrate CRUDAdmin into a FastAPI App (Sessions, Auth, and Initialization)

## Background
CRUDAdmin is a modern admin interface for FastAPI with built-in authentication and security features (CSRF protection, rate limiting, IP restrictions, HTTPS enforcement, and secure cookies). It supports multiple session backends (memory, Redis, Memcached, database, hybrid). The library is experimental and introduced breaking session configuration changes in v0.4.0 (constructor-based configuration).

## Use Cases
- Add an authenticated admin UI for SQLAlchemy models in a FastAPI service.
- Initialize database tables and the admin interface safely at application startup.
- Prepare production-ready session storage by switching from in-memory sessions to Redis or Memcached.

## Inputs
- A FastAPI application.
- SQLAlchemy async engine and models (e.g., `User`) plus Pydantic schemas (`UserCreate`, `UserUpdate`).
- A `SECRET_KEY` value.
- Optional: Redis or Memcached configuration for production session storage.

## Outputs
- A FastAPI app with CRUDAdmin mounted at `/admin`.
- Admin views registered for your SQLAlchemy models.
- (Optional) Session backend configured for Redis or Memcached.

## Steps
1. Install CRUDAdmin.
   - With `uv`:
     - `uv add crudadmin`
     - Optional Redis extras: `uv add "crudadmin[redis]"`
   - With `pip` (example memcached extras): `pip install "crudadmin[memcached]"`
2. Create an async SQLAlchemy engine for your database (example uses SQLite + aiosqlite).
3. Implement a FastAPI dependency that yields an `AsyncSession` from the engine.
4. Instantiate `CRUDAdmin` with:
   - `session=get_session` (your session dependency)
   - `SECRET_KEY="..."`
   - Optional `initial_admin` credentials for first-time bootstrap.
5. Register your models with `admin.add_view(...)`, providing:
   - `model=...`
   - `create_schema=...`
   - `update_schema=...`
   - `allowed_actions={...}` (e.g., `{"view", "create", "update"}`)
6. Add a FastAPI `lifespan` handler to ensure tables are created and the admin interface is initialized before serving requests.
7. Create the FastAPI app with `lifespan=lifespan`.
8. Mount the admin app: `app.mount("/admin", admin.app)`.
9. If using SQLite, add DB artifacts to `.gitignore` so sensitive data (including admin credentials and session tokens) is not committed.
10. For production session storage, configure a non-memory backend such as Redis (constructor-based configuration in v0.4.0+).

## Verification
Run a small script that builds the app, initializes it via the lifespan, and verifies the `/admin` mount is present.

```python
# verify_crudadmin_mount.py
# Expected outcome:
# - Prints: "OK: /admin is mounted"
# - Completes without exceptions

import asyncio
from contextlib import asynccontextmanager

from fastapi import FastAPI
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine

from crudadmin import CRUDAdmin

engine = create_async_engine("sqlite+aiosqlite:///app.db")

async def get_session():
    async with AsyncSession(engine) as session:
        yield session

admin = CRUDAdmin(
    session=get_session,
    SECRET_KEY="your-secret-key-here",
    initial_admin={
        "username": "admin",
        "password": "secure_password123",
    },
)

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Note: Table creation depends on your SQLAlchemy Base/models.
    # This verification focuses on admin initialization + mounting.
    await admin.initialize()
    yield

app = FastAPI(lifespan=lifespan)
app.mount("/admin", admin.app)

async def main():
    async with app.router.lifespan_context(app):
        paths = {r.path for r in app.routes if getattr(r, "path", None)}
        assert "/admin" in paths, f"/admin not mounted; routes={sorted(paths)}"
        print("OK: /admin is mounted")

if __name__ == "__main__":
    asyncio.run(main())
```

## Safety
- Do not commit SQLite database files (they may contain sensitive data such as admin credentials and session tokens). Add patterns like `*.db`, `*.sqlite`, `*.sqlite3`, and database journal files to `.gitignore`.
- CRUDAdmin is experimental; upgrades may introduce breaking changes. Read release notes before upgrading, especially for session backend configuration changes introduced in v0.4.0.
- Use a strong `SECRET_KEY` and avoid hard-coding production secrets in source code.
