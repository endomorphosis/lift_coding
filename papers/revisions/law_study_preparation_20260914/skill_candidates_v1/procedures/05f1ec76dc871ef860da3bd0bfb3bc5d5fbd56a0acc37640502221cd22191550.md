# Add Two-Factor Authentication to a Symfony App with scheb/two-factor-bundle (and plan upgrade to scheb/2fa-bundle)

## Background
This repository provides two-factor authentication (2FA) for Symfony applications and includes multiple second-factor methods (TOTP/Google Authenticator, email codes) plus features like trusted devices, backup codes, multi-factor authentication, CSRF protection, and whitelisted routes.

The repository and its 4.x branch are unmaintained. Newer versions are available as `scheb/2fa-bundle` from the `scheb/2fa` repository. Use this skill to quickly integrate the bundle where you must stay on older Symfony versions, and to capture the explicit upgrade path to the maintained bundle.

## Use Cases
- Add TOTP/Google Authenticator 2FA to an existing Symfony application.
- Add email-based authentication codes as a second factor.
- Enable trusted devices/backup codes to reduce lockouts.
- Prepare an upgrade plan from unmaintained 4.x to maintained `scheb/2fa-bundle` (v5+).

## Inputs
- A Symfony application codebase.
- Composer access to install PHP packages.
- Choice of 2FA method(s): TOTP/Google Authenticator and/or email authentication codes.
- Source documentation path: `Resources/doc/` in the repository.

## Outputs
- Composer dependency installed: `scheb/two-factor-bundle`.
- Bundle configured per the repository documentation.
- A documented upgrade note/action item to move to `scheb/2fa-bundle` (v5+) from `scheb/2fa`.

## Steps
1. Confirm whether you can use the maintained bundle: if possible, target `scheb/2fa-bundle` from <URL> (v5+). If you must use this repo, continue with the steps below.
2. In your Symfony project root, install the bundle via Composer:
   - `composer require scheb/two-factor-bundle`
3. Open and follow the bundle installation guide referenced by the repository:
   - `Resources/doc/installation.md`
4. Choose and configure one or more 2FA methods as supported by the bundle:
   - TOTP authentication
   - Google Authenticator
   - Authentication code via email
5. Enable CSRF protection as supported by the bundle (documented in `Resources/doc/`).
6. Configure trusted devices and/or trusted IPs if your risk model allows it (documented in `Resources/doc/`).
7. Configure single-use backup codes to reduce account lockouts (documented in `Resources/doc/`).
8. If you need more than one second factor step, configure multi-factor authentication (documented in `Resources/doc/`).
9. Define whitelisted routes that must remain accessible during the 2FA flow (documented in `Resources/doc/`).
10. Review repository security guidance:
   - `SECURITY.md`
11. Add an internal upgrade task to move off 4.x (unmaintained) to `scheb/2fa-bundle` (v5+) from `scheb/2fa`.
12. Record the selected method(s) and the relevant `Resources/doc/` pages in your project’s security documentation/runbook.

## Verification
Run these checks from your Symfony project root.

```bash
# 1) Verify the dependency is installed and Composer can resolve it.
composer show scheb/two-factor-bundle
# Expected outcome: command prints package details (name/version/description), indicating it's installed.

# 2) Verify Composer autoload is consistent after adding/configuring the bundle.
composer dump-autoload -o
# Expected outcome: completes successfully without errors.
```

## Safety
- This repository’s 4.x branch is unmaintained; plan and schedule an upgrade to the maintained `scheb/2fa-bundle` (v5+) from `scheb/2fa`.
- Trusted devices/IPs can reduce user friction but may reduce security if misconfigured; ensure they match your threat model.
- Backup codes reduce lockout risk; protect them as sensitive authentication material.
