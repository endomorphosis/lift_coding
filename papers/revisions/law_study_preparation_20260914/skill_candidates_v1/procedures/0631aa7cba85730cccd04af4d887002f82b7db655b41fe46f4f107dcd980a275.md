# Build and Configure the ModSecurity v3 Nginx Connector

## Background
ModSecurity-nginx is the Nginx connector module for ModSecurity v3. To use it, Nginx must be compiled with the connector module, and ModSecurity rules must be enabled and configured in Nginx.

## Use Cases
- Compile Nginx with the ModSecurity v3 connector as a static module.
- Compile Nginx with the ModSecurity v3 connector as a dynamic module.
- Enable ModSecurity per server/location and load rules from a local file, a remote endpoint, or inline configuration.
- Add a per-virtual-host ModSecurity transaction ID tied to Nginx request IDs for improved tracing.

## Inputs
- Nginx source tree (to run `./configure`).
- Path to the ModSecurity-nginx module source directory.
- libmodsecurity installed on the build system.
- One of:
  - A local ModSecurity rules file path (e.g., `/etc/my_modsecurity_rules.conf`), or
  - A remote rules endpoint URL plus key, or
  - Inline ModSecurity rules content.

## Outputs
- Nginx built with the ModSecurity-nginx connector (static or dynamic module).
- Nginx configuration enabling `modsecurity on;` and referencing rules (file/remote/inline).
- Optional: Nginx logs containing request IDs and ModSecurity transaction IDs.

## Steps
1. Install libmodsecurity on the build host (required before compiling this connector).
2. Obtain the ModSecurity-nginx source and note its filesystem path (referred to below as `/path/to/ModSecurity-nginx`).
3. Choose a build mode:
   - Static module: `--add-module=...`
   - Dynamic module: `--add-dynamic-module=... --with-compat`
4. From the Nginx source directory, configure Nginx with the connector:
   - Static:
     - `./configure --add-module=/path/to/ModSecurity-nginx`
   - Dynamic:
     - `./configure --add-dynamic-module=/path/to/ModSecurity-nginx --with-compat`
5. Build and install Nginx using your standard Nginx build/install process for your environment.
6. Enable ModSecurity in an Nginx `server` block:
   - Add `modsecurity on;`.
7. Configure rules from a local file (example):
   - In a relevant `location` block, set `modsecurity_rules_file /etc/my_modsecurity_rules.conf;`.
8. Alternatively, configure rules from a remote endpoint (example):
   - In a relevant `location` block, set `modsecurity_rules_remote my-server-key <URL>
9. Alternatively, configure inline rules for a specific location (example pattern shown below):
   - Use `modsecurity_rules ' ... ';` inside the `location`.
10. (Optional) Add an extended log format that includes `$request_id`, and set a ModSecurity transaction ID using that request ID.
11. Configure separate virtual hosts with distinct `modsecurity_transaction_id` prefixes to make cross-host tracing easy.
12. Reload or restart Nginx using your standard operational procedure.

```bash

```

## Safety
- Compiling Nginx with additional modules changes the runtime surface area; validate changes in a non-production environment before deployment.
- Ensure ModSecurity rules (local/remote/inline) are reviewed and tested to avoid false positives that can block legitimate traffic.
- If enabling debug logging (e.g., `SecDebugLog`), be mindful of log volume and sensitive data exposure.
