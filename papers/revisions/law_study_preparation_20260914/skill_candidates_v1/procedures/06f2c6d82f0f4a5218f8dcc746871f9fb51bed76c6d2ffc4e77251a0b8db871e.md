# GraphQL field-level authorization with graphql-rule

## Background
graphql-rule is a Node.js library for defining per-field access rules (authorization) on “model” objects. It provides hooks to allow/deny access before reading a field (`preRead`), after reading a field based on the value (`read`), and a failure handler (`readFail`) that can return a fallback value or throw.

## Use Cases
- Enforce field-level authorization rules on objects returned by a GraphQL API.
- Fail fast on expensive fields (e.g., fields that trigger network calls) using `preRead`.
- Redact or replace unauthorized field values using `readFail`.
- Apply consistent, reusable authorization policies via shared interfaces.

## Inputs
- A Node.js project with npm.
- Rule model definition options passed to `Rule.create({ ... })`:
  - `name` (required): unique model name.
  - `base`: base class extending `Model` from `graphql-rule`.
  - `props`: lazily computed cached getters available via `model.$props`.
  - `defaultRule`: default field rule (`preRead`, `read`, `readFail`).
  - `rules`: per-field overrides and metadata (`type`, `list`, `readListItem`, `method`, `cache`).
  - `interfaces`: model classes to inherit static/prototype behavior from.

## Outputs
- A rule model class created by `Rule.create(...)` that enforces the declared field access policies when fields are accessed/called.

## Steps
1. Install the package in your Node.js project:
   - `npm install --save graphql-rule`
2. In your codebase, import the library:
   - `import Rule from 'graphql-rule';`
3. Create a rule model class with a unique `name` using `Rule.create({ ... })`.
4. Define `defaultRule.preRead` to allow/deny access before the field is accessed (useful for failing fast).
5. Define `defaultRule.read` to allow/deny access after the field is read (useful for decisions based on the field value).
6. Define `defaultRule.readFail` to control behavior on denial:
   - return a replacement value, or
   - implement a function that returns a value or throws.
7. Add per-field rules under `rules` to override `preRead`, `read`, and/or `readFail` for specific fields.
8. For nested object fields, set `rules[fieldName].type` to a model name or model class so the value is wrapped as that model.
9. For list fields, set `rules[fieldName].list = true` and optionally implement `readListItem` to filter items.
10. For function fields (methods), set `rules[fieldName].method = true` so the rule system treats the field as callable.
11. If you need computed, cached derived values shared across multiple fields, add lazy getters under `props` and read them via `model.$props.<propName>`.
12. If you have shared rule behavior, define a common model and include it via `interfaces` to inherit rules/props.

## Safety
- Be deliberate with `readFail`: returning `null` (or another fallback) can silently hide authorization issues; throwing can surface unauthorized access more explicitly.
- Use `preRead` to avoid triggering expensive or sensitive operations when access should be denied.
- When using `type`/`list` wrapping, ensure nested objects and list items also have appropriate rules to prevent data leakage through traversal.
