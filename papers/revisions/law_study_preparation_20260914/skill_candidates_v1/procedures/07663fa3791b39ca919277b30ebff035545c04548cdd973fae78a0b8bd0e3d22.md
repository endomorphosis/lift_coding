# Fastly Compute OAuth 2.0 + OpenID Connect (OIDC) Auth Starter (Google Example)

## Background
This skill configures an OAuth 2.0 / OpenID Connect authentication flow at the edge using a Fastly Compute service and an identity provider (IdP). It includes a concrete example using Google as the IdP, including how to obtain and embed the OIDC Discovery document and JSON Web Key Set (JWKS) into `fastly.toml` for local testing.

## Use Cases
- Add login (OAuth 2.0 + OIDC) to a Fastly Compute service.
- Validate ID tokens at the edge using the IdP’s JWKS.
- Stand up an end-to-end authentication flow locally before deploying.

## Steps
1. Create a Google OAuth client ID in Google API Console:
   - Go to Google API Console → APIs & Services → Credentials.
   - Create Credentials → OAuth client ID.
   - Choose **Web application** and name it.
2. Add local testing URLs to the Google OAuth client:
   - Authorized JavaScript origins: `<URL>
   - Authorized redirect URIs: `<URL>
   - (These are for local testing; plan to remove them later.)
3. Save the issued credentials into gitignored secret files in the repo root:
   - Put the client ID into `.secret.client_id`.
   - Put the client secret into `.secret.client_secret`.
4. Create a strong nonce secret file in the repo root:
   - Generate 32 bytes of randomness and base64-encode it into `.secret.nonce_secret`.
5. Fetch Google’s OIDC Discovery document and JSON-stringify it for embedding:
   - Download from `<URL>
6. Paste the JSON-stringified Discovery document into `fastly.toml`:
   - Set `openid_configuration` under `[local_server.config_stores.oauth_config.contents]`.
7. Read `jwks_uri` from the OIDC Discovery document and fetch the JWKS.
8. JSON-stringify the JWKS document and paste it into `fastly.toml`:
   - Set `jwks` under `[local_server.config_stores.oauth_config.contents]`.
9. Start the local development server for your Compute service.
10. In a browser, open `<URL>
11. Complete the end-to-end OAuth 2.0 flow.
12. Once local auth works, build and deploy your Fastly service and obtain a domain.

## Verification
Run the following checks from the repository root.

```bash
set -euo pipefail

# 1) Verify the OIDC discovery endpoint is reachable and includes jwks_uri
curl -fsS https://accounts.google.com/.well-known/openid-configuration \
  | jq -e '.jwks_uri and (.jwks_uri|type=="string")' > /dev/null
# Expected: exits 0

# 2) Verify the JWKS endpoint returns at least one key
curl -fsS https://www.googleapis.com/oauth2/v3/certs \
  | jq -e '.keys and (.keys|type=="array") and (.keys|length>0)' > /dev/null
# Expected: exits 0

# 3) Verify required secret files exist and are non-empty

# Expected: all tests succeed
```

## Safety
- Keep `.secret.client_id`, `.secret.client_secret`, and `.secret.nonce_secret` gitignored and out of logs.
- Local URLs (`<URL> and `/callback`) are for local testing; remove them from the IdP configuration before production.
- Treat embedded `openid_configuration` and `jwks` in `fastly.toml` as configuration data; update if the IdP rotates endpoints/keys.
