# Authenticate to Xbox Network (Xbox Live) in Node.js using @xboxreplay/xboxlive-auth

## Background
@xboxreplay/xboxlive-auth is a lightweight, zero-dependency Node.js library that performs Xbox Network (Xbox Live) authentication with OAuth 2.0 support. It can return an XSTS token and user hash suitable for calling Xbox Network APIs.

The project notes breaking changes since v4; basic usage of `authenticate()` remains backward compatible, but advanced imports/features changed.

## Use Cases
- Obtain `user_hash` and `xsts_token` for calling Xbox Network APIs.
- Inspect each authentication step by enabling raw response mode.
- Customize authentication with a specific XSTS RelyingParty, sandbox, and selected display claims.
- Call Xbox Network endpoints using the bundled XSAPI client or by constructing headers manually.

## Inputs
- Node.js project (TypeScript or JavaScript).
- Xbox/Microsoft account credentials (email + password) for `authenticate()`.
- Optional `AuthenticateOptions`:
  - `raw: true` to return per-step responses
  - `XSTSRelyingParty` (example: `<URL>
  - `optionalDisplayClaims` (example: `['gtg', 'xid']`)
  - `sandboxId` (example: `RETAIL`)

## Outputs
- Standard authentication response (typical fields):
  - `xuid` (may be null depending on RelyingParty)
  - `user_hash`
  - `xsts_token`
  - `display_claims` (varies by RelyingParty)
  - `expires_on`
- Raw authentication response when `raw: true`:
  - An object keyed by hosts (e.g., `login.live.com`, `user.auth.xboxlive.com`, `xsts.auth.xboxlive.com`) mapping to each step’s response.

## Steps
1. Create or open a Node.js project directory.
2. Install the library:
   - `npm install @xboxreplay/xboxlive-auth`
3. Implement basic authentication using `authenticate(email, password)`.
4. (Optional) Enable raw response mode with `authenticate(email, password, { raw: true })` to debug the flow.
5. (Optional) Customize XSTS token creation using options such as `XSTSRelyingParty`, `optionalDisplayClaims`, and `sandboxId`.
6. Capture `user_hash` and `xsts_token` from the result for API calls.
7. Call Xbox Network APIs either:
   - using the library’s XSAPI client (`XSAPIClient.get(...)`), or
   - manually with HTTP headers: `Authorization: XBL3.0 x=<user_hash>;<xsts_token>` and `X-XBL-Contract-Version`.
8. If you maintain older code (v4-era), review the migration guide referenced by the project before adopting granular module imports.
9. If the account requires 2FA, note that the exposed `authenticate` method cannot handle it; consider OAuth2 flows with refresh tokens as described in the library docs.

## Verification
Run a local end-to-end check that authenticates and validates the presence of required fields.

```bash
# Expected outcome:
# - Prints a JSON object containing at least: user_hash, xsts_token, expires_on
# - Exits successfully

cat > verify-xboxlive-auth.mjs <<'MJS'
import { authenticate } from '@xboxreplay/xboxlive-auth';

const email = process.env.XBOX_EMAIL;
const password = process.env.XBOX_PASSWORD;

if (!email || !password) {
  throw new Error('Set XBOX_EMAIL and XBOX_PASSWORD environment variables before running this check.');
}

const result = await authenticate(email, password);

for (const k of ['user_hash', 'xsts_token', 'expires_on']) {
  if (!result?.[k]) throw new Error(`Missing expected field: ${k}`);
}

console.log(JSON.stringify({
  user_hash: result.user_hash,
  xsts_token_prefix: String(result.xsts_token).slice(0, 16),
  expires_on: result.expires_on,
}, null, 2));
MJS

node verify-xboxlive-auth.mjs
```

## Safety
- Treat `xsts_token`, refresh tokens, and credentials as secrets; do not log full tokens, commit them to git, or paste them into tickets.
- Prefer short, redacted logs (e.g., token prefix) and store secrets in environment variables.
- Be aware of the limitation: `authenticate()` cannot handle 2FA; using a 2FA-enabled account may require OAuth2 refresh-token-based flows.
- `xuid` and `display_claims` can vary with the selected RelyingParty; design downstream code to handle missing/nullable fields.
