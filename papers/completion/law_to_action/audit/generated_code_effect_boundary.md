# Generated-code effect boundary: independent inspection

Read-only source audit, 2026-09-11. This is supporting material for LA-002 and later harness work, not an LA-002 deliverable, completed experiment, selected protocol or runtime change. Paths below are relative to `external/ipfs_accelerate/ipfs_accelerate_py/agent_supervisor/` unless a repository prefix is written explicitly.

**An independent Python syntax extractor exists, but its output is not a measurement of actual handler effects.** The paper needs to qualify the trusted source-loading and execution wiring around it. A second function with the same name accepts caller-supplied effect labels; it must not be mistaken for the syntax extractor.

Two tests illustrate the evidence distinction. `external/ipfs_accelerate/test/api/test_agent_supervisor_cve_security_gate.py:172` builds `_code_facts` manually with labels such as `write`, `resource:repository` and synthetic identities. Those are gate-conformance fixtures. Its test at line 244 genuinely calls the syntax extractor on literal before/after Python containing `sink(payload)`, then expects `invoke`, target `sink`, flow `name->argument:sink`, effect `call`. That establishes a useful executable test definition, not an executed experiment in this audit or a full generated-program safety result. `test_agent_supervisor_code_security_facts.py` separately specifies dynamic-call, unsupported-source and changed-scope checks.

The second `extract_code_security_facts` lives at `proof/security_contract_analysis.py:2533`. It constructs path/symbol/tag/effect records from caller arguments, with `effect:<path>` as a fallback label; it is not the AST implementation above. The fixed-point caller in `validation/deterministic_doctor_live_fixed_point.py:726` supplies `tags_by_path` and `effects_by_path`, and defaults missing intent effects to the code-effect list. This is a separate contract path. Do not cite it as independent IntentIR-versus-generated-code analysis without establishing the actual upstream producers and the chosen invocation's inputs.

A bounded textual call-site search across the three canonical Python packages (`ipfs_accelerate_py`, `ipfs_datasets_py`, `ipfs_kit_py`) found definitions/exports, but no direct production calls to `evaluate_cve_security_gate(...)` or `compile_cve_pre_execution_admission(...)`. Tests do call the gate. Dynamic dispatch, imported aliases, untracked worktrees and external callers may exist; this search does not establish universal absence. LA-002 should name the real selected runtime entry point and demonstrate its wiring before claiming complete mediation.

## Minimal counterexample requirement for later harness work

This is a proposed diagnostic obligation, not a chosen benchmark case or executed test. Use harmless instrumented sandbox handlers: an intended `allowed_sink(payload)` call and a candidate containing an undeclared `other_sink(payload)` call. Load actual before/after files through the trusted adapter, extract facts, retain both independent intent and code mappings, and carry their exact roots/identities through admission into the enforce-mode host wrapper. Observe a separate counter at each real handler. A rejected candidate must produce zero forbidden-handler calls; a matched permitted control must still perform useful work. A helper's reject label without reaching the same protected handler boundary is insufficient evidence.

Also inspect a dynamic call and an unchanged helper whose behavior is reached by changed code: this extractor observes changed Python scopes and does not follow imports, so its diagnostics/dependency coverage must determine whether such a candidate is supported. Do not replace missing resource/effect semantics with invented labels merely to obtain an exact mapping. No sample sizes, baseline arms, outcome values or universal safety claim are fixed by this note.
