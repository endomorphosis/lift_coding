\section*{2  Representations and training examples}
\subsection*{2.1  What is shared, and what is learned?}
\noindent
Three axes must remain distinct. Source format names prose, code, traces, tables, or extracted media.\linebreak[4]
Domain names Legal, Security, Intent, software, or UI declarations. Logical view names deontic,\linebreak[4]
temporal, frame, first-order, cognitive/event, graph, or proof-oriented structure. Sharing canonical\linebreak[4]
records does not equate domain ontologies or logical interpretations. [artifact S01--S06]\linebreak[4]
The domain-neutral kernel supplies canonical bytes, identities, provenance, source spans, assumptions,\linebreak[4]
claims, obligations, and result protocols. Domain adapters retain their own semantic slots. The syntax\linebreak[4]
kernel supplies typed terms, binders, signatures, connectives, and versioned family extensions. A\linebreak[4]
symbolic declaration is therefore discrete and inspectable; its CID identifies an encoding under a\linebreak[4]
declared profile, not a learned location in a vector space. Equal vectors or nearby embeddings do not\linebreak[4]
imply equivalent formulas. [artifact S01,S05]\linebreak[4]
Six intermediate objects have different roles: canonical symbolic declarations, family-specific\linebreak[4]
formulas, learned numerical features, graph relationships, search plans, and proof/evidence records.\linebreak[4]
A search plan is not a formula; a declaration is not its verification result; and a vector is not a proof.\linebreak[4]
Their interchange requires explicit mappings. A model can select or repair a candidate without\linebreak[4]
defining its semantics. [artifact S01,S04,S34,S38]\par

\subsection*{2.2  How examples and supervisory targets are constructed}
\noindent
The concrete legal training record contains source identity and citation, raw and normalized text,\linebreak[4]
an embedding-model identifier and vector, a modal IR document, frame candidates and selection,\linebreak[4]
parser trace, and losses. A builder normalizes a U.S.-Code-style passage, parses modal formulas,\linebreak[4]
ranks ontology frames using BM25, and packages the result. The default convenience embedding is\linebreak[4]
explicitly a deterministic mock; the local codec can instead supply spaCy-derived feature hashing,\linebreak[4]
and externally supplied vectors carry their producer identity. Experiments must record which path\linebreak[4]
supplied the target vector. [artifact S22,S23]\linebreak[4]
Thus targets are not all human gold labels. Modal-family targets can be derived from parsed operators;\linebreak[4]
view targets come from bridge contracts and their configured scoring; frames can be retrieval-selected;\linebreak[4]
and proof-feedback labels require admitted verifier records. Reproducing these labels measures\linebreak[4]
distillation of those teachers. Independent annotations and held-out semantic distinctions are required\linebreak[4]
to measure fidelity to the original source.\linebreak[4]
For a source x, write I = C\ensuremath{\psi} (x) for the symbolic compiler output, e = T (x) for the declared embed-\linebreak[4]
ding target, and f = F (x, I) for reusable features. Features include lexical cues, actor/action/object\linebreak[4]
roles, conditions and exceptions, temporal structure, predicate arity, quantifier scope, provenance,\linebreak[4]
frame relations, compiler contracts, and reconstruction diagnostics. The adaptive model predicts an\linebreak[4]
embedding \^{e}, a modal-family distribution pF , and a view distribution pV . Some features depend on\linebreak[4]
an existing parse, so this is often parser-assisted learning, not a demonstrated raw-text-only universal\linebreak[4]
compiler. [artifact S24]\par
