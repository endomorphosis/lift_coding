                                                         Abstract

 1             Coding agents repeatedly reconstruct repository state, regenerate plans, and re-
 2             run validation, yet shorter prompts or cached passes can omit dependencies and
 3             weaken assurance. We present an obligation-centered architecture that maintains
 4             content-addressed semantic state separately from operational task state and durable
 5             evidence. A formalization layer maps code, intent, and applicable constraints to
 6             typed obligations while exposing unsupported or lossy translations. A supervisor
 7             uses these obligations to select deterministic analysis, compositional reasoning,
 8             proof search, bounded synthesis, or an explicitly authorized neural residual. Candi-
 9             date edits are checked against current source; test and proof results are admitted
10             only for their declared statements, environments, and trust profiles. Accepted
11             transitions update durable roots and invalidate affected planning and verification
12             state. The design includes incremental proof-unit sealing and staged fixture-aware
13             test reuse, semantic-world memory, and procedural synthesis. We specify separate
14             tests of preservation, progress, and end-to-end cost, including matched raw-context
15             baselines, cold validation oracles, and positive authorization cases. [RESULTS:
16             insert the frozen task population, useful completion rate, net measured cost,
17             uncertainty intervals, and false-admission results.] The contribution is a method
18             for governing repository evolution with explicit evidence, not a claim that hashing,
19             model confidence, or every available solver proves arbitrary Python correct.


20   1    Problem and contribution

21   The cost of an agent is not only the tokens used to generate a patch. It includes rediscovering
22   relevant code, reconstructing assumptions, choosing tests, recovering interrupted work, and deciding
23   whether previous evidence still applies. Repository agents and automated testing studies make the
24   quality of the agent–tool boundary central to useful repair [8, 11]. Here, that boundary is a persistent
25   state-and-obligation representation rather than an unstructured conversation history.
26   Our proposed method has three linked contributions. First, it compiles source and domain intent into
27   identity-bound semantic evidence and explicit unresolved obligations. Second, it makes planning,
28   counterexample-guided repair, and procedural synthesis consumers of those obligations, retaining
29   neural models only for unresolved proposals. Third, it separates test observations, proof statements,
30   reuse decisions, and accepted state transitions, enabling incremental work without silently upgrading
31   evidence. Semantic context reduction is one measurable consequence of this loop, not its sole
32   purpose.
33   The prototype contains source-present components and incompletely qualified integration paths. This
34   working paper distinguishes those from methods specified in active workstreams and from results
35   actually measured. Source presence, branch landing, operational consumption, passing qualification,

38   2     State and evidence are typed, separate authorities

39   2.1   The persistent state model

40   Let F be a frozen repository forest, including source trees, declared overlays, dependency pins, and
41   relevant environment identities. The incremental semantic index extracts stable symbols, semantic
42   versions, typed relationships, and limitations. A separate semantic-state producer seals the finalized
43   index into immutable facts, links, capsules, and environment bindings. It supplies pure selection and
44   freshness operations; it does not execute tests, operate a task queue, or decide that a candidate is
45   accepted. [D1]

46   2.2   Claims carry provenance and applicability

47   The domain-neutral IR kernel separates declarations, runs, results, and receipts. A declaration does
48   not acquire a different semantic identity because a model or solver ran. Canonical identities bind a
49   schema/domain and canonicalization profile; operational roots can reference declarations and their
50   histories without inserting attempts, clocks, or leases into semantic content. Legal, Security, and
51   Intent families share these protocols but do not share verdict authority or ontology. [N4]

58   2.3   Incrementality with a visible unknown frontier

59   Previous and current semantic states drive additive invalidation and test/proof selection. Fresh exact
60   dependency capsules may substitute for unchanged source under a declared profile; edited targets,
61   stale records, and opaque or insufficient analyses require exact source or broader validation. Dynamic
62   dispatch, reflection, fixtures, plugins, external services, and generated code can prevent a complete
63   dependency closure. Unknown edges widen the frontier rather than disappear from it. [D1; W1–W2]

64   3     Formalization: preserve the property before proving it

65   3.1   Domain intent is not execution authority

66   A high-level objective is first a candidate specification. Intent IR expresses goals, actions, resources,
67   and effects; Legal IR contributes applicable normative constraints; Security IR contributes principal,
68   resource, and effect invariants. Their shared IR kernel supplies canonical claims and evidence
69   references, not an automatic equivalence between domains. Reviewed formalization and source
70   mappings turn a candidate into bounded obligations; ambiguity, missing coverage, and unsupported
71   modalities remain explicit. [N4–N7]
72   The attested authorization design queries a manifest-bound proof corpus, checks applicability and
73   revocation, composes obligations, and produces an exact-context decision. Correctness and authoriza-
74   tion are separate gates. The inspected reference enforcement layer supports one-time consumption
75   and context rechecks, but does not itself connect to real tools; the documented receipt-consumption
76   rollout defaults off/shadow. Thus the paper claims an interface and mechanism only at the deployment
77   stage actually exercised. [N7, N11]


78   3.2   Loss-aware translation and solver-state limits

79   A target formula is useful only for claims preserved by its translation. For example, a legacy projection
80   removes temporal/deontic operators and approximates a binary temporal formula by conjunction.
81   A proof of that projection cannot prove the original obligation. The admitted route must reject
82   unsupported loss or bind an independently justified preservation relation. Translation validation
83   checks the particular transformation rather than trusting every conversion [4]. [N8]
84   The inspected incremental SMT wrapper maintains named assertions and replay identity but rebuilds
85   a Z3 solver per check; that path supplies no exported proof object. It therefore supports assertion-
86   level incrementality, not an established retained-clause speedup. Solver diversity, same-solver core
87   rechecking, native proof reconstruction, and kernel checking must be reported separately. [D2]
88   The actual component checker lowers a producer guarantee G and consumer assumption A to G ∧
89   ¬A; SAT supplies a countermodel, UNSAT discharges the encoded implication, and unsupported
90   clauses remain uncovered. The bounded QF_LIA CEGAR adapter searches a Boolean abstraction,
91   concretizes an error trace, and refines only spurious traces using validated predicates. A feasible trace
92   refutes the model; incomplete search is not a proof. These results become reasoned plan obligations
93   and localized repair inputs. [N12–N13]

94    4     Planning and state repair before neural execution
95    4.1   Objective compilation and plan admission

96    The direct-objective workstream replaces manual prompt elaboration with a bounded compiler:
97    authorized input and repository scan yield goals, subgoals, task dependencies, assumptions, permitted
98    effects, exact outputs, and acceptance obligations. Deterministic templates cover known task families.
99    A model may propose a residual decomposition, but the result must pass schema, dependency, scope,
100   resource, and acceptance-coverage checks. An inferred specification is still a proposal until admitted;
101   a model must not lower the objective or remove a required test to make its own plan succeed. [W2;
102   DOEP]
103   Planning maintains an obligation frontier. Resolved obligations reference current evidence; unre-
104   solved obligations carry a reason and a permissible next route. Hard authority, safety, and effect
105   conditions are checked before ranking by cost. The intended routing policy selects the cheapest
106   adequate route, not a ritual invocation of every theorem prover.

113   4.2   A routing gate is not a proof kernel

114   The pre-implementation kernel can defer unavailable capabilities, choose a unique analytical can-
115   didate, abstain on ambiguous candidates, or authorize a named neural residual using resolved task/
116   forest-bound receipts. It does not run a model, prove a candidate, or by itself complete a task. A
117   Boolean “closes claim” on a candidate requires independent downstream justification. Its local zero
118   provider-hook count is not a measurement of saved model calls across the workflow. [A1, N1]
119   Integration is part of the method. The real caller must bind the current plan, diagnostic view and
120   obligation graph to the same task and forest as its evidence. A valid authorized residual must progress
121   while a minimally altered invalid request fails. Measuring only rejection would reward a deny-all
122   agent rather than useful neurosymbolic control.

123   4.3   Event-driven reassessment and bounded convergence

124   Repository, dependency, policy, proof, fixture, capability, and owner events invalidate only the
125   affected causal/semantic frontier when that frontier is complete. The supervisor retains accepted
126   unaffected subplans and emits a PlanDelta rather than rebuilding an entire prompt. Refill creates
127   only tasks needed for explicit gaps or counterexamples, subject to plan epochs, generation limits,
128   repeated-candidate detection, and authority. Unknown provider effects enter reconciliation rather
129   than blind retry. [W2; DOEP]
130   Queue exhaustion is not success. Completion requires current evidence covering every mandatory
131   acceptance obligation and no unresolved required consumer. Bounded termination is also not con-
132   vergence to a solution: budget exhaustion, nonconvergence, unavailable tools, and human decisions
133   remain separate terminal outcomes. Incoming world-model self-hosting is qualified only when route
134   and acceptance records show actual consumption of state, not merely sidecar logging. [W1–W2]

135   5     Repair, context compilation, and procedural synthesis
136   5.1   Localize and preserve the intended change

137   A repair begins with a state-bound failed obligation, observation, or counterexample—not a free-form
138   request to “fix everything.” Static dependency analysis and abstract interpretation bound the affected
139   region. Assume–guarantee checks expose unmet component interfaces; validated unsat cores or
140   interpolants can identify a compact missing premise. CEGAR refines an abstraction after a spurious


                                                        4
141   counterexample; CEGIS refines candidate implementations against accumulated counterexamples
142   [3, 5]. Conflating these loops would obscure whether the program or its abstraction changed.
143   Candidate plans, patch sketches, and CodeEditPackets remain non-authoritative. The currently
144   represented path checks preimages and scope, applies a Git patch in an isolated fenced worktree,
145   rescans semantic state, and runs selected plus required fallback validation. General tokenizer-alias IR
146   editing and exact CST/AST relinking remain separate PCSM extensions until their actual resolver,
147   renderer, round-trip and adversarial checks are frozen. A source map alone is not a proof of semantic
148   preservation.

149   5.2   Context minimizes unresolved information, not obligations

150   The semantic compiler owns semantic ContextPack identity and sufficiency; the runtime compiles
151   provider-facing ContextCapsules. The goal, authority, scope, and acceptance core is non-truncatable.
152   Optional evidence is chosen under byte/token budgets; exclusions have exact expansion references
153   and reason codes. Required target source, caveats, tests, and proof obligations cannot be removed
154   to hit a compression target. Parent-bound delta capsules carry new counterexamples or dependency
155   facts while retaining the invariant core. Stable prefixes and provider cache reuse remain bound to
156   model/tokenizer/policy identities. [D1; ASEH, PCSM]
157   A model request names the residual question, admitted evidence, missing information, budget,
158   expected response schema, and independent acceptance test. Failed candidates expand only implicated
159   source or contracts when possible. This adapts abstraction refinement to context selection without
160   claiming that every context heuristic is a sound program abstraction.

161   5.3   Compile repeated successful work into bounded operators

162   ProcedureCegis already implements a bounded synthesis state machine. Its source order is existing
163   verified procedure, built-in template, anti-unified pattern, declarative/constraint candidate, model
164   sketch, and human candidate. Candidate and counterexample-set identities prevent repeated evaluation
165   of the same pair. The synthesizer neither executes nor certifies nor promotes its output. [A2]
166   The incoming memory method mines independently admitted trajectories, preserves failed episodes,
167   infers applicability conditions, and validates anti-unified procedures on held-out families. Each
168   procedure has typed parameters, effects, branch/loop bounds, residual holes, rollback, and required
169   validation. Execution must recheck current applicability and authority. Learned call-target, event-
170   delta, inverse-trace, and repair-delta models rank constrained candidates or abstain; their predicted
171   transitions become accepted state only after observation or verification. [W2, W4]
172   Architecture refactoring applies the same loop to module boundaries and state ownership: SCC-based
173   candidates, compatibility contracts, source-preserving edits, differential traces, tests/proofs, and
174   rollback. A smaller dependency graph, fewer files, or lower context burden only ranks candidates; it
175   does not establish equivalence. [W4]


176   6     Test certificates and sound conditions for reuse

177   6.1   Specify exactly what is certified

178   A test certificate must name its statement, source/dependency roots, runner and environment, fixture
179   inputs, result semantics, and checker/trust profile. “Verified” is not a single universal evidence class.
180   A manifest can be complete while its child observations depend on a trusted runner; a circuit can
181   correctly verify signatures while proving nothing about honest execution by their signer. [K1, A5]
182   The source-present Groth16 adapter is gated by explicit opt-in and a compiled Rust backend, with
183   BN254 and versioned circuit references. Its inspected derivation helper accepts only propositional
184   atoms, facts, and one-antecedent implications, using forward chaining. This is not the full temporal/
185   deontic system and not a CPython/pytest execution model. Versioned wrapper code, setup availability,
186   and attestation metadata must not be mistaken for a qualified circuit/key ceremony or measured
187   prover performance. [N9–N10]

188   6.2   Fixture-aware, phase-aware applicability

189   The PCTDD workstream separates collection seed, fixture-definition closure, materialized fixture-
190   instance commitment, pre-call execution key, and post-execution setup/call/teardown evidence. It
191   binds parametrization, plugins/hooks, conftest, autouse fixtures, DI adapters, external snapshots,
192   clocks/RNGs, interpreter, policy, and relevant hardware. Arbitrary Python object serialization is
193   not a sound dependency model. Setup/call reuse may not silently skip required resource effects or
194   teardown; a teardown failure prevents a whole-item pass. Opaque dependencies force execution.
195   [W3]

196   6.3   Exact reuse and cross-tree reuse are distinct

197   A full-tree cache key changes on an unrelated edit. Broader reuse therefore needs a current dependency
198   projection and a noninterference/applicability witness, not just removal of the tree from a key. If
199   a deterministic observation under profile θ is a function fθ of a complete projection πD, then
200   πD(s)=πD(s′) implies equal observations. This conditional argument is elementary; proving that πD
201   includes all relevant inputs and effects is the hard obligation. Runtime traces alone cannot show that
202   no unobserved dependency exists. [W3; Appendix I]

203   7     Incremental proof state and durable acceptance
204   7.1   Completeness is independent of membership

205   Verification is partitioned into source-addressed proof units with stable logical identities and complete
206   applicability/trust keys. A requirement manifest declares every mandatory unit; a proof forest binds
207   the evidence for those units in deterministic categories. Merkle membership proves inclusion, not
208   that the collector included all required tests. Selection completeness and authorized removal of
209   obligations are separately checked. Delta seals name the accepted parent and exact reused, replaced,
210   added and removed units; uncertainty forces broader verification or a full checkpoint. [A5, K1]

211   7.2   Prepared artifacts cannot publish themselves

212   The durable store persists canonical blocks and candidate evidence; the supervisor runtime decides
213   whether evidence satisfies current obligations. The small persistence adapter and actual pointer CAS
214   are separate surfaces. Current-seal publication checks repository/branch identity, expected parent and
215   generation. Local locks, atomic filesystem publication, and WAL recovery do not constitute global
216   distributed consensus or a transaction spanning Git, the task database, and remote services. Crash
217   recovery must explicitly reconcile those boundaries. [K1–K4]

237   7.4   Multi-agent and world-state extension

238   Sibling supervisors exchange typed requests, observations, and receipts, not writable access to
239   each other’s state. Mergeable observational indexes can nominate dependencies; exclusive claims,
240   fences, policy, publication, and completion remain transactional. Accepted world roots can compose
241   semantic, program-trace, logical-dataset, procedure, proof, and environment roots. Cyclic logical
242   graphs use stable IDs and snapshot manifests rather than literal cyclic content links. Required-mode
243   operation must exhibit pre-state consumption, accepted transition evidence, and post-state publication.
244   [W1–W2; DOEP]

245   8     Evaluation: useful progress, preservation, and cost
246   8.1   Primary comparison and independent oracles

247   Freeze a task population, model revisions, exact repository forest, tools, policies, budgets, and
248   acceptance criteria before running paired conditions. The core A/B comparison changes only raw/
249   lexical versus semantic context; later arms add routing, incremental verification/reuse, and governed
250   lifecycle. These combined arms measure package effects, not the isolated contribution of each
251   mechanism. Orthogonal ablations must isolate translation checking, symbolic routing, context
252   selection, proof reuse, parallel preparation, and procedures. [ASEH; PCPR]

253   8.2   Populations and controls

254   Use exact pre-fix historical tasks, held-out task/repository families, and controlled adversarial cases.
255   Hide target patches and acceptance oracles from proposal generation; generated tests may supplement
256   but not silently replace the oracle. Include valid authorized actions as well as invalid ones. Seed
257   lost modalities, inconsistent assumptions, removed tests, missing fixture inputs, stale maps/keys,
258   changed verification keys, unknown provider outcomes, and crashes around publication. Keep
259   failures, timeouts, abstentions and unavailable routes visible.
260   Measure successful accepted tasks per fixed budget, false acceptance and false denial, conditional

275   9     Evidence limits, related work, and conclusion
276   9.1   What the existing artifacts establish

277   The reviewed standalone repository heads and the consumer’s dependency pins differ. A final claim
278   must bind the actual loaded source forest, including overlays, native binaries, solver/circuit profiles
279   and active rollout settings. Source-present intent authorization and a Groth16 wrapper must not
280   be described as always-on enforcement or a validated universal prover. The preceding integration
281   findings belong in the author audit until resolved or reported as limitations.

282   9.2   Relationship to established methods

283   Proof-carrying code attaches checkable policy evidence to untrusted code [1]; abstract interpretation
284   and CEGAR reason over approximations and refine them with counterexamples [2, 3]. Translation
285   validation checks a produced transformation, and CEGIS searches bounded candidates against
286   counterexamples [4, 5]. Equality saturation represents alternatives under rewrite relations [6]. These
287   are foundations, not newly invented algorithms in this work.
288   The intended difference is composition at the agent’s operational boundary: persistent semantic
289   state, explicit obligations, residual model authorization, phase-aware test evidence, and accepted-
290   transition publication. Build-system research separates scheduling from rebuilding [7]; our reuse
291   design additionally exposes statement, fixture, trust and authority conditions. Coding agents and
292   test-generation benchmarks [8, 11], premise-retrieval and hammer systems [9, 10], and prompt
293   compression [12] provide relevant baselines. We do not claim that this is the first neurosymbolic
294   agent or that combining these techniques automatically improves performance.

295   9.3   Limitations and accountable self-improvement

296   Python reflection, native code, external state, concurrency, incomplete specifications, and unsound
297   translations limit what can be proved. A sound checker cannot repair an incorrectly formalized
298   requirement. Default-deny behavior can mask broken positive paths. A self-improving supervisor
299   must not edit its own protected acceptance specification, keys, validators or promotion policy under
300   ordinary task authority. Every learned update or compiled procedure requires an independent holdout
301   and rollback gate.
302   Important model use in implementation, formalization, candidate generation, experiments and
303   manuscript preparation must be disclosed accurately. The final claims remain conditional on the
304   frozen evidence and tested deployment. Our thesis is that persistent obligations can displace repeated
305   neural reasoning and validation while preserving a declared acceptance standard; the paired evaluation
306   must determine whether the total benefit exceeds the added analysis and proof cost.

411   D     Semantic objects, projection indexes and logical datasets
412   D.1   Semantic objects and relations

413   Wrap existing domain-state CIDs in adjacent versioned semantic-object envelopes containing domain,
414   schema, canonicalization profile, provenance, source CIDs, optional declared policy salt and evidence
415   class. Do not alter the existing source-semantic root to include embeddings, prompts, actors, leases,
416   wall time or transition history. Pure semantic deltas remain distinct from operational execution
417   records. [W1, W2]
418   Relations are scoped claims such as equivalent, refines, entails, contradicts, compatible_with and
419   supersedes. Each binds left/right objects, scope, assumptions, environment and theory/policy, proof/
420   evidence references, limitations and invalidation dependencies. “Similar” belongs to a retrieval
421   projection, not the authoritative semantic relation vocabulary. Exact CID equality establishes byte
422   identity, not universal semantic equivalence. [W1]

423   D.2   Hybrid retrieval without authority leakage

424   Projection records bind their semantic object, projection kind, model, tokenizer, preprocessor, dimen-
425   sion, metric, normalization, vector identity and privacy policy. Rebuildable index manifests bind
426   generations and model/projection compatibility. Lexical, vector, LSH/Hamming, graph or neural
427   search may nominate candidates. The resolver must retrieve exact object bytes, verify current root
428   membership and recheck freshness, environment, obligations and policy before use. A stale vector or
429   approximate neighbor never substitutes for an exact subject. [W1, W2]
430   The graph-to-graph or typed-attention TAGSeq/DAGSeq idea remains an optional experimental
431   projection over typed program neighborhoods. It must be compared with exact lookup, rules, ordinary
432   graph features and embedding-only baselines. Canonical symbols and typed source maps remain
433   authoritative even if the learned projection changes. [W2]

434   D.3   Logical data versus physical layout

435   LogicalDatasetState and PhysicalDatasetLayout must not collapse into one identity. Under a fixed
436   logical schema, key/order policy and provenance, changing Parquet row groups, compression or
437   shard packaging should preserve logical content identity while changing layout identity. Set, multiset
438   and ordered semantics must be explicit; duplicate and key-conflict behavior cannot be inferred from
439   file order. [W1]
440   Transformations bind exact inputs, transformation specification, environment/toolchain, candidate
441   outputs and validation evidence. Merges use a closed declared semantics—append, keyed three-way,
442   ordered, set/multiset, schema evolution or conflict. Distributed workers may prepare shards and
443   candidate layouts, but only accepted logical state and validated provenance may enter a world root.
444   Legacy or mock dataset managers cannot silently remain production semantic authorities. [W1, W2]

445   D.4   VFS bridge

446   A successful canonical VFS/worktree mutation emits a durable post-commit receipt and semantic
447   outbox record. Rescanning, invalidation and acceptance occur through the existing semantic and
448   supervisor authorities. Filesystem success alone is not task success; recovery handles an outbox that
449   exists before semantic acceptance, and all side effects remain attributable to exact operations. [W1,
450   W2]

629   I.3     What can be proved about acceptance and reuse

630   I.3.1    Accepted-lineage invariant — proof sketch, not machine checked
631   Fix a statement profile Θ and a policy predicate PΘ over artifact manifests. Assume: the initial
632   accepted root satisfies PΘ; all required subject bytes and dependency references are verified; the
633   manifest is complete under an admitted completeness rule; each accepted evidence item satisfies its
634   designated checker relation; the sole publication operation enforces the expected parent and all gates;
635   and protected policy/checker identities cannot change under worker authority.


                                                          22
636   Then every root reachable solely through accepted publication transitions satisfies PΘ. Proof:
637   induction on the number of successful publications. The initial case is assumed. For the induction
638   step, the publisher checks PΘ on the exact candidate manifest and current parent before its CAS
639   linearization; failed or stale attempts are not successors. The induction does not establish any property
640   omitted by PΘ, truth of unsupported translations, honest signed observations, or atomicity of external
641   side effects.

642   I.3.2    Dependency-projected test reuse — proof obligation
643   Let Obsθ(t,s) be the relevant setup/call/teardown observation of test t in state s under a declared
644   runtime/effect profile θ. Suppose a complete projection πD and deterministic function fθ exist such
645   that Obsθ(t,s)=fθ(πD(s)) on all states admitted by the reuse policy. If πD(s)=πD(s′), equality of
646   the observations follows immediately. An admitted previous observation can therefore transfer only
647   within that profile and those assumptions.
648   The difficult part is establishing completeness and determinism of πD. Definitions alone miss fixture
649   values; function coverage misses plugin, clock, network, DB and teardown effects. Two equal digests
650   of incomplete manifests do not satisfy the premise. For effectful tests the profile must also show that
651   required effects are replayed or observationally unnecessary. Otherwise run setup and/or the test
652   and teardown. A cold oracle and adversarial mutations check the implementation but do not prove
653   universal closure.

654   I.3.3    Three acceptance questions, three different answers
655              Behavioral claim: does candidate program/model satisfy its obligation?
656              Action permission: may this actor perform this action now?
657              Publication: does this candidate and its evidence become current?
658   Neither a proof of behavior nor a capability alone answers all three. Formalization determines
659   the statement; authorization binds actor, tool, arguments, resources, effects, scope, time and roots;
660   execution observations report what happened; publication chooses the accepted lineage. The reference
661   pre-dispatch code uses an in-memory consumption ledger and fake-dispatch defaults, so durable
662   real-tool integration requires its own adapter and restart evidence. [N7, N11]

663   I.3.4    Useful autonomy requires positive-path witnesses
664   Require a paired witness for each gate: a correctly authorized, well-bound case that progresses and a
665   minimally altered case that is rejected. Include a deny-all control in safety/cost diagnostics, not as a
666   competitive repair method. Otherwise default deferral, unavailable backends or adapter mismatches
667   can masquerade as perfect safety and low inference cost.

708   L     How symbolic computations change the next agent action
709   L.1   Abstract state supplies candidate bounds

710   The inspected Python abstract interpreter uses a product of flat constants, integer intervals, nullness,
711   exceptions and effects. Its immutable lattice protocol exposes order, join, meet, widening and
712   narrowing; the adapter records local interprocedural summaries and source positions. The worklist
713   accumulates possible states at program points. Unsupported reflection, native calls, loading and
714   callbacks widen to opacity. A consumer may prune an impossible candidate only under a sound
715   admitted approximation, never from a learned low score. [N14]

                     Abstract state = Const × Interval × Nullness × Exceptions × Effects.                 (4)

716   L.2   Interface composition creates a precise discharge job

717   A CompositionEdge references exact producer/consumer contracts and named normal, exceptional
718   and induction clauses. Unknown clause references are rejected before solver execution. The compo-
719   sition graph and receipt bind the semantic root, contracts, edges, obligation outcomes, uncovered
720   assumptions and SCCs. Its basic implication query is G ∧ ¬A. SAT provides a countermodel;
721   UNSAT provides solver-backed discharge of that encoded implication. Opaque prose stays uncovered.
722   Cycles need a typed invariant plus an independently solved closure check rather than mutually citing
723   guarantees. [N12]

                         G ∧ ¬A is UNSAT        ⇒     G ⇒ A (in the encoded theory).                      (5)

724   This permits a caller to consume a dependency guarantee instead of repeatedly loading its body
725   only when current bindings, statement coverage and the consumer assumptions hold. A contract


                                                        25
726   gap becomes a named repair or proof task. Consistency and reachability checks prevent treating an
727   impossible guarantee as meaningful implementation correctness.

728   L.3   CEGAR localizes abstraction error before code repair

729   The QF_LIA adapter searches a supplied Boolean abstraction of a control-flow graph and constructs
730   a named concrete path formula for each abstract error trace. A feasible path is retained as a
731   real counterexample. A spurious path may be refined with a validated interpolant/core, weakest
732   precondition, or reviewed predicate. Iteration, predicate, abstract-state and trace-length budgets
733   are explicit; unavailable, unknown, timeout and budget exhaustion are separate dispositions. It is a
734   refinement adapter over existing contracts, not a second unrestricted model checker. [N13]

               A ⇒ I,        I ∧ B is UNSAT,         Symbols(I) ⊆ Symbols(A) ∩ Symbols(B).                (6)

735   Those are the checks required for an interpolant at the shared boundary. An unsat core identifies

746   The following algorithm is retained from the preceding evaluated draft as an intended composition,
747   not a newly executed implementation result. It is a control-flow specification retained for comparison
748   with the final executable artifact.

749   Algorithm 1: Intended composed supervision loop. Input: authorized q, current source forest F,
750   policy P, budget B

751        1. reconcile event, task and artifact state; refresh F and derive G, O
752        2. if cancelled or budget exhausted: return explicit non-success
753        3. if every current obligation is admitted: return verify_goal_completion()
754        4. generate bounded task proposals; preview and separately admit ready work
755        5. if no task is admissible: return wait_or_review(), not goal success
756        6. claim task; bind lease/fence, preimages, required context and validation
757        7. choose deterministic, authorized residual-model, review or unavailable route
758        8. if review/unavailable: record blocked attempt; return to the event service
759        9. produce and apply candidate only through checked isolated execution
760       10. rescan; derive O_new from authorized rules, not the worker’s pass claim
761       11. verify/reuse evidence; retain failed, unknown and pending obligations
762       12. if refinable failure: record new residual; return bounded retry to service
763       13. if evidence incomplete or unsafe: return defer_or_reject()
764       14. persist manifest; recheck current bindings; CAS the expected parent
765       15. if publication conflicts: return reconcile(), not completion
766       16. record accepted task transition and updated F, G, O; reevaluate at line 1
767       17. propose procedure/policy learning separately; never self-promote

768   This algorithm specifies the composition to evaluate. Passing tests of isolated stop paths does
769   not establish the complete loop; qualification must exercise useful authorized progress as well as
