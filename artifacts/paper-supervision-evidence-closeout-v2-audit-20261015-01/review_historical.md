# Independent review of generated evidence projections

Scope: reviewed generated workstream reports, findings, run/session ledgers, encoder projections and proof observations only. No new original evidence was read, and no model, solver, build, grader or runtime action ran. This is a review of the projections and their internal claims, not a second authentication of originating artifacts. The historical workstream was authored by this reviewer, so its review is a self-check; the T1, T2/T4 and cross-IR projections were independently reviewed.

## Findings requiring care in the combined report

1. **Do not pool unlike row units into an experiment count.** Historical runs contain Requests event joins, reuse case pairs, timing pairs and Horn proof/control observations. T1 mixes historical development attempts, a final pair, later retrieval attempts and a frontier lead; T2 includes earlier cohorts. A combined ledger row count is neither a benchmark sample size nor a denominator of independent repair trials. The generated outputs correctly preserve distinct cohorts. Keep unit/cohort/profile columns visible in derived tables.

2. **Rename the T2/T4 table's final column.** It currently says “Reported incomplete total,” but populated cells include rows whose `native_usage_complete` is true, including the 228,630 native control and several older successful/failed rows. `known_token_subtotals` is a reported-counter field, not an automatic incompleteness flag. Use “Retained reported total (completeness separate)” or show that column only where completeness is unknown. Prefer “Reported complete native total” for the other column: raw provider-log authentication was not rerun in this audit. This is a presentation correction, not a changed observation.

3. **Preserve three usage schemas.** Codex includes cached input within input and reasoning within output. Historical Requests/direct-Grok reports use input + visible output + disjoint reasoning, with cache a subset of input. Grok CLI X1 counts fresh input + cached input + cache-write input + output as disjoint categories; reasoning inclusion is unknown. A provider name alone cannot choose the schema. Keep all original semantics and do not add a normalized reasoning charge where none was observed. Per-call counters in historical_sessions are intentionally unavailable; do not divide event totals among the 23 call IDs. Session and invocation IDs are distinct identity kinds.

4. **Distinguish expected axiom checks from recovered actual output.** T2 proof projection contains `expected_axioms_checks` strings and a receipt reporting executed Lean kernel replay, plus theorem/transcript CIDs and binary/source hashes. This supports a retained wrapper/receipt claim for the narrow header guard. It does not by itself recover an actual `#print axioms` transcript or independently verify exact theorem bytes. State the local contract scope and Python/WSGI translation assumptions. Do not promote it into the paper's evidence-algebra theorem, full-program correctness, complete SecurityIR discharge or final accepted-root publication. The projection correctly preserves `security_ir_obligations_discharged=false`, 217 omitted files and `pending_native_stop` publication.

5. **Keep cross-IR status per domain and trial.** The generated cross-IR matrix is current-source inspection; T1 separately invoked preplanning but failed open without an Intent checkpoint. “Actually invoked” here denotes the advisor stage, not successful learned intent inference. Source384 prediction invocation in T3/T4/X1 with zero training does not qualify repository-adapted inference. T1 has distinct source-learning updates, but no held-out qualification or established 384D domain identity. Do not join these records into a single successful five-IR trace or infer that repository adaptation trained LegalIR, IntentIR or UI/UX semantics. No per-trial Legal/UI applicability or independently admitted host action chain is recovered.

6. **Training metrics are narrow development observations.** The standalone Intent roundtrip projection has 75/75 authored versus 0/3 weak-public holdout results and zero-head 0/78. Report both groups; do not present 75 successes as natural-language intent generalization. It records an inherited 8D lexical branch, not a demonstrated 384D Intent deployment. The checkpoint backend exceeds the inspection bound, so its descriptor commitment is not fresh byte verification. Source-trained examples and task-side public smoke/evaluation files require explicit permitted-source provenance; filenames alone neither prove leakage nor establish clean holdout separation.

7. **Arithmetic success is not authenticity.** Fresh checks verify transcribed/report-derived counters, explicit schema sums, identifiers and bounded artifact hashes. They do not independently authenticate raw logs, verify signatures, rebuild immutable runtime archives, reexecute original acceptance checks or prove loaded-module closure. Complete native usage flags remain separate from unknown auxiliary/pipeline accounting, dollar settlement and nested clocks. Current report commits are not executed forests.

## Internal identity check

No duplicate non-null run IDs were found across the three generated run ledgers, and no duplicate non-null session IDs were found across their session ledgers. This is a projection consistency check only: reused controls represented by different aliases still need explicit `same-control-as` edges, and null IDs are not deduplication evidence.
