# Typed header proof admissions through the Terminal host

The explicit Terminal host can observe native scoped header proofs with their
current bound admission handles and independently expected generic receipt IDs.
This connects the [scoped header cache bridge](82-supervisor-scoped-header-cache-bridge-2026-10-12.md)
to the signed task/source/context lifecycle. The local theorem retains its
assumptions, residual obligations and scope; completion, execution, publication,
replacement and required-fact omission remain unauthorized.

`TerminalFormalStatusOwner` retains its five original inputs and adds optional
exact tuples for `header_proof_admissions` and independent `(key_id, receipt_id)`
pairs in `expected_receipt_ids`. Both must cover the entire requested population,
without duplicates or partial/foreign bindings. Expected identities are not
inferred from handles. Exact gate, analysis object, complete key bytes, receipt
and path joins precede proof-owner observations. These checks follow the existing
initial Terminal preparation/context I/O. A raw Terminal host gate/key tuple
refuses scoped receipts without the bound inputs; ordinary `@1` receipts retain
their behavior.

The generic census's bound `@2` lane validates every positive receipt against its
independently expected identity, calls the native handle's currentness guard and
uses its bound render method. The complete guard runs after the final generic
denial-state consultation, preserving combined quarantine/tombstone refusal and
final source/custody checks. Misses or rejected expected positives refuse this
bound population rather than becoming measured zeros. Explicit empty populations
remain distinct from missing inputs. Absent new fields preserve legacy binding
payloads and their canonical digests.

Terminal independently replays signed task/source/context and retains original
handles, gate, analysis and populations across entry and exit. Native guard checks
cover original sealed SQLite/HMAC proof lineage, exact generic cache/state objects,
file identities, current profiles, bounds, implementations and executable pins.
Pure joins bracket host callbacks. Recursive same-handle currentness and stage
operations refuse. Import performs fresh kernel replay during separate host setup;
the Terminal census checks existing admission handles without executing a kernel
or constructing proof owners.

Private observation state controls final revalidation. Changing exported status,
host/currentness flags or counts cannot skip the bound check. Replacing the nested
report refuses and invalidates the original escaped reference. Fresh results
update the same dictionary; error invalidation restores a private canonical
snapshot before applying refusal, clearing caller-added fields and authority
flags. Initially refused populations retain their original refusal. Native-only
proof drift clears nested currentness and accepted counts while the independent
outer Terminal task/source/context can remain current. Existing caller-exception,
task/source and cleanup guards remain enforced.

Operation counters describe direct adapter calls. Bound rendering and guard calls
perform further native source hashing, lineage checks and SQL transactions. These
counters do not measure complete native lookup cost or provider-token usage.
Canonical error invalidation restores initial nested counters, while outer
cumulative totals may already include a later completed observation. Refused
nested counters do not guarantee the latest attempted operation costs.
Sequential validation grants no atomic lease or future-eligibility guarantee.
Native bookkeeping can write the existing owner. Requested budgets do not certify
OS resource enforcement, and receipt byte caps do not bound native lineage work.

run token savings remain unmeasured.
