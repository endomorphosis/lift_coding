## Behavior and limits

The new binder requires the exact scope value and independent scope/inventory
pins, existing CAS, request, limits, current repository and context. Replayed
metadata must match completely, including required/program roles and unselected
frontier. It derives the exact selected paths through the existing live native
claim/grant binding. It keeps the legacy method and native wire shape unchanged.

Reentry through either binder refuses. Input/scope/CAS mutation and stale claims
or current originals refuse. A failure after publication keeps the actual reader
consumed; it does not rollback or silently rebind. The detached observation checks
the original scope/reader/CAS, current committed population, complete historical
replay and live native task, with another source check after the closing native
coordinator callback. Currentness checks remain sequential, not an atomic lock
across task, filesystem and CAS.

Native task and source-binding verification are reported independently from
historical provenance. Allocation, compiled context, coding process, proof,
execution, completion and omission flags remain false. The observation is not a
serialized capability. Nomination limits remain 64 files and 1,000,000 original
per-path bytes; the existing coding-child broker still has its 32-path ceiling.

The positive test uses a real claimed task, coordinator, owner grants, DuckDB,
Git/CAS and owner-side broker reads. Quack listener lifecycle and deployment
metadata are authored fixtures. It verifies selected bytes and refuses an
unselected path; it does not establish an authenticated remote coding child or
managed allocation ownership for this handoff.

## Preserve the complete task profile

A fully signed Terminal semantic/read selection remains separate work. Current
preparation, vector qualification, partitioning, loaders, task-data deferral and
rebind all expect complete signed profile/worker populations. Preserve complete
`input_paths` and explicit mandatory support; do not shrink the signed task
inventory to implement scoped reads.

A postcommit source inventory includes the generated public task profile.
Embedding that inventory CID inside the same profile creates a content cycle.
Keep a future signed selection declarative, then bind its profile hash, inventory,
nomination and native context identities in a later checked receipt. Reconcile
the existing parallel sessions/compiler/planning stack and its same-named policy
schema collision while retaining distinct IR/dimension/schema/task inventories.
No competing repository sessions or database owner were introduced here.
