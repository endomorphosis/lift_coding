# Numerical obligation retrieval from isolated coding workers — 2026-10-12

The numerical index previously exposed an owner-side API, while the isolated
coding process could see only its bounded planning summary. The supervisor now
provides a task-bound read-only service that the existing `llm_router` coding
session can invoke with a pinned standard-library-only CLI. The shared datasets
pager remains responsible for native source/report replay and exact pagination.

The owner creates a protected descriptor from the sealed implementation prompt
and validated task context. The router joins that descriptor to the task,
context bundle, numerical receipt, source tree, allocated workspace and container
boundary before exposing it to child tools. Each request must originate beneath
the exact launched worker process birth; a matching UID alone is insufficient.
Neither the request nor the public descriptor grants access to private catalogs.

Each page checks the canonical and allocated source snapshots before and after
retrieval. An edit invalidates the old context. Full rows are preserved, with an
8,192-byte JSON envelope limit, at most eight rows, 64 session connections and
524,288 prepared response bytes. The service lifetime follows the coding
timeout, separately from the existing 90-second startup handoff. Startup,
execution and shutdown failures close the service and retire its descriptor.

The mandatory numerical summary advertises the command, so its guidance enters
the complete coding input. Owner audits retain request/response hashes, sizes,
row counts and delivery outcomes. The benchmark collects these after worker
cleanup and before container removal, matching them to the admitted task and
router receipt. Missing or incomplete evidence produces unavailable counts;
an interrupted in-flight request cannot silently become a zero measurement.

The full exercise, including deliberate repeated/filter queries, recorded 36
requests, 29 successful pages, 97 row deliveries and 134,039 response bytes.
Those 97 deliveries are not unique coverage. Frame prefixes and the CLI newline
are outside the JSON size budget; provider token accounting must include the
entire actual tool interaction.

Local validation passed 528 cases before merging the concurrent source-lookup
work, then 568 cases on the merged source: zero failures, errors or skips,
with unchanged production bytes during both runs. A fresh Docker qualification
also passed on the merged runtime. Local documentation and link gates passed.

An explicitly authored `generate_text` hook drove the real worker route. No
model, provider, solver, checkpoint inference or official benchmark verifier was
called. This qualifies the worker retrieval path; it does not establish a live
model's tool choice, full supervisor START, task success, formal proofs or token
savings. All 45 numerical source obligations remain pending. The earlier live
token comparison remains historical, and a new controlled live comparison is
still required.

The merge preserves the parallel current-source lookup implementation on the

container route; this numerical endpoint does not automatically authorize it.
