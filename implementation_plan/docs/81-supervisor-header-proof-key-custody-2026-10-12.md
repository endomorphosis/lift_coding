# Scoped header proof keys and native restart custody

The production scoped header recipe can now prepare a complete Doctor key from
current signed source and retain its canonical inputs beside the original sealed
proof. Restart replay requires independently rebuilt inputs and a full expected
key identity, checks the original native owner and sealed lineage, and reruns
the pinned kernel. This addresses the missing key-input custody in the earlier
Terminal host-owner work. It does not establish generic positive-cache
acceptance, live Terminal receipt coverage or token savings.

Preparation replays exact source, candidate AST and optional SecurityIR joins;
captures the actual executable bytes, configuration, commands and translator;
and binds the theorem, source premise, scope, AST/import graph, explicit host
profiles and requested bounds. Corpus, registry, policy, sandbox and environment
profiles require concrete versioned native identities. Diagnostic placeholders
cannot substitute for them. The diagnostic snapshot retains its original source
corpus, while admitted proof profiles enter the theorem/key separately.

The native contract's `witnesses` field contains static AST source observations.
A reviewed, versioned source-premise projection retains every observation
visibly under a closed AST vocabulary. Its exact inverse restores the complete
original contract and CID. The original contract remains the logical premise
reference; the projection has its own distinct artifact CID. Extra/private
fields, corrupted correspondence or a caller-forged observation refuse. The
general private-material classifier is unchanged.

Successful proof reports now retain the final sealed authoritative reference.
With explicit complete profiles, a bounded custody record is sealed in the same
SQLite owner. The private seal key remains private. Helpers construct no Gate,
cache or replacement owner, and restart performs no locator discovery. Current
source, implementations, profiles, both executable pins and bounds must match.
Owner paths, strong object references, device/inode, authority/store identities
and original seal-key bytes remain checked around native operations.

Checks are sequential, not an atomic lease. Requested resource limits are inputs,
not certification of OS CPU/memory/network enforcement. Initial proving and
custody persistence append records; restart reloads the retained lineage and
reruns the kernel without appending a new sealed record in its adapter. Record
byte bounds do not bound native lineage-prefix work or arbitrary executable
filesystem effects. Historical proof CIDs alone cannot recover omitted final
references.
