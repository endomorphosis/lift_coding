# Bounded current-source lookup on the existing supervisor owner

The supervisor now serves selected exact original source through a bounded
`source.get` operation on its existing typed owner. It separately checks
historical CAS byte integrity, native task revision/body custody and full
selected working-file equality. A trusted parent can launch the credential-isolated
CLI, issue a grant for that exact child process and receive one canonical reply.

The [implementation and guide](https://github.com/endomorphosis/ipfs_accelerate_py/blob/e8694753cbe11e5b10eaf2d33eb257a705f07783/docs/agent_supervisor/current_source_lookup.md)

## What is qualified

**44 distinct cases passed**, zero failures/errors/skips: 29 actual source-owner
controls, four real child CLI cases, seven wire controls and four current native
owner regressions. Normal AST sealing and isolated process state remained enabled.
Final source/test hashes matched before and after the run. The fixture uses actual
local DuckDB and typed Unix sockets with a hermetic Quack transport; the native
Quack extension network and live coding models were not qualified here.

Each grant contains only `source.get` and exact native task, repository and tree
scopes. Peer/process birth, grant expiry/revocation, original owner/connection,
generation/fence/database UUID and native task revision/body are rechecked.
The host supplies the public path scope and context identity; an inventory's
historical task label does not establish native custody. Source/store callbacks
cannot silently substitute the admitted CAS, inventory or request/limits.

Every read checks the complete native committed population and clean visible
index state, then compares full selected working bytes and Git owner-execute mode
to retained original bytes. No-follow directory descriptors and a complete parent
and leaf rewalk detect pathname replacement. A final file check follows native
callbacks. Clean newline/filter conversion still refuses if disk bytes differ
from the committed source. Dirty/staged/untracked/hidden overlays, stale identities,
corrupt artifacts and foreign/forged/consumed cursors refuse.

Default slice and complete response caps are 4 KiB/16 KiB, with hard 16 KiB/64 KiB
ceilings. Full-envelope counters include metadata, encoded content, continuation
and the final CLI LF; the wire counter substitutes the four-byte frame prefix.
The source lane refuses oversized frame headers before body acquisition and
requires canonical received JSON. Shortened slices retain an explicit remaining
byte frontier. Cursors must actually be issued to the same grant and are retained
in bounded ephemeral memory. No new database, content owner or model asset is made.

Failed runs are retained. Initial collection selected a stale legacy test that
imports a symbol already removed in base main; it was replaced with current
owner regressions. The first real owner run caught indexed `DuckDBRow` decoding:
iteration yields names, and the fix compares values without weakening the fence.
The next run passed 19 cases before the CRLF fixture's stale index stat failed its
clean-status premise. The corrected controls refresh the same blob and assert
unchanged HEAD/tree/blob identity; no product change was needed for that correction.
Repetitions do not increase the 44-case count.

## Remaining integration and measurement

This first profile has one binding per gateway lifetime and supports selected
clean committed regular files. Changed tasks/source/context require a separately
admitted refresh lifecycle. Symlinks/Gitlinks, dirty overlays and mapped compact
edits remain separate scopes. Checks are sequential without a filesystem writer
lease. Each slice still replays the complete historical inventory and reads the
selected file in full under the owner lock, so cost and contention can be high.
Partial slice hashes rely on the authenticated owner for whole-source membership.
No proof, edit, omission, repository-completion or token-saving authority is granted.

Current coding containers do not yet receive a qualified session/descendant
channel. Provider subprocesses do not preserve this credential descriptor into
model-spawned shell processes, and those processes have different grant peers.

multiple task bindings and current overlay refresh inside allocated workers;
reuse the published numerical pager and add capsule reads through separately
admitted operations. Rebuild a current worker archive, qualify actual model use,
then compare complete rendered inputs and all native planning/coding/lookup/
continuation/repair usage against official rewards. Preserve failed lookups and
unknown usage. The parallel pager's 45 pending rows and 263 tests are a separate
qualification; it discharged zero source-correctness obligations.
