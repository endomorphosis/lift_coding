# Supervisor loop formalization and retrieval qualification

The new explicitly selected `python-numerical-control-structure@3` profile
represents numerical Python loops and conditional control in the shared datasets
ProgramIR grammar, then carries their unresolved proof scopes through supervisor
planning, DuckLake indexes, publication successors and worker retrieval.

The public `largest-eigenval` fixture now has four structurally complete
functions, up from three in the guarded profile. Both timing loops are represented;
105 obligations remain pending. Top-level `eval.py` assignment/main-guard handling
remains partial. This work establishes no source-semantic proof, learned-decoder
coverage increase, new benchmark score or token saving.

Iterator state slots prevent repeated producer evaluation. Advance-only
exhaustion is distinguished from escaping exceptions, and nested `else` transfers
retain their actual active loop target. Invariants, exit reasoning and termination
have distinct proof scopes; their source-expression anchors do not establish
applicability. First-order expressions retain this scope even when extracted from
their enclosing report. CFG edges do not supply a reviewed TLA+/transition-system
interpretation. Runtime effects, reachability, invariants and termination remain
unverified.

The Docker fixture used the production owner launcher, a separate worker UID,
`llm_router` implementation runner and numerical broker, with authored planning
and provider hooks and networking disabled. It did not execute a live model,
learned Source384/IntentIR inference, full supervisor START or an official verifier.
Five private owner paths were denied; broker descriptors/socket and the container
were removed. A writable base and root setup supported the existing sudo worker
transition. These are bounded custody checks, not a general sandbox security proof.

Two earlier fixture attempts exceeded the existing 64-request quota by repeating
filter reads after the full scan. The final fixture removes those repeats while
retaining every peer/cursor/source-staleness check; successful filter combinations
are covered by regressions. Production quotas remain unchanged. The complete
session has no spare request. Byte accounting excludes IPC frame prefixes and
has no provider-token interpretation.

Local documentation gates and explicit report/evidence links passed. Hosted
[documentation run 38363087750](https://github.com/endomorphosis/ipfs_accelerate_py/actions/runs/38363087750)
for the exact integration revision failed before running any steps:
GitHub reported the account locked for a billing issue, with runner ID zero.
The [CI observation](../../artifacts/numerical-loop-publication-20261013/hosted-ci.json)

and [parent checks](../../artifacts/numerical-loop-publication-20261013/parent-checks.json)

## Remaining work

This closes the prior function-level loop coverage gap, while leaving operational
semantics, refinement witnesses, invariant/progress synthesis, module
initialization, complex targets, exception handlers and async control unresolved.
The compact summary does not inline all obligations; full proof scopes require
retrieval. Exhaustively reading the richer records increases transport bytes.
A live benchmark comparison must select relevant obligations and charge context,
retrieval and model usage before claiming token efficiency. The earlier native
metadata comparison remains the latest live performance evidence.
