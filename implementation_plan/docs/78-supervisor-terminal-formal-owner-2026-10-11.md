# Explicit Terminal host custody for formal-status observations

Terminal can now receive an existing native Doctor proof owner and complete
key population through an explicit host entry point. It checks those inputs
against its actual admitted task, signed source scope and indexed context. The
coding prompt and worker arguments remain unchanged; the native owner and keys
stay in the supervisor host. Default preparation still has no admitted proof
population and leaves accepted coverage unknown.

`TerminalFormalStatusOwner` carries an existing `ScopedDoctorAnalysis`,
`DoctorProofCacheGate`, immutable complete key tuple, independently pinned
owner-path digest and independently expected key identities. Terminal rebuilds
the signed scope, checks repository/task/admission and scope roots, and joins
forest/tree/overlay/candidate-tree logical identities. The signed scope is
distinct from the manifest source tree and Git commit. Canonical key preimages,
proof profiles and the expected population remain explicitly host admitted;
matching a logical ID or hashing a caller declaration does not authenticate them.

Current Terminal/source checks bracket native consultation. A measured lane
observes again on context exit while retaining the original cache/path/device/
inode binding. The nested dictionary updates in place, so escaped references
also lose currentness and accepted counts when custody fails. Native revocation
or owner replacement visible during the checks refuses qualification. Source,
task, context and cleanup failures invalidate the observation. Per-pass native
counters and accumulated consultation counts remain operational evidence,
separate from provider-token usage. Native gate bookkeeping can write the
existing owner; this does not create another production cache.

Both observations are sequential and precede Git cleanup. They do not provide
an atomic owner snapshot, proof eligibility at return, or a substitute for fresh
render/commit revalidation. A miss leaves an obligation open. Denied or refused
requests retain null accepted coverage. Repeated-status populations and live
token savings remain unknown.

The production gap is now precise: existing Doctor workflows persist sealed
SQLite receipts and observational proof-scope indexes, while the new census
requires a complete admitted Doctor DuckDB Gate/key population. The transaction
cache-binding probe is injectable but has no current producer. No cache path,
proof key or accepted proof is inferred from task JSON, candidate IR, a catalog
identifier or a sealed-store locator.
