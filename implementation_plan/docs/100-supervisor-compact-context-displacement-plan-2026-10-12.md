# Compact context, repository round trips and total supervisor tokens — 2026-10-12

The token-efficiency plan now distinguishes complete retained source storage,
bounded coding-worker navigation, safe propagation of edits and execution of
transformed code. The immediate priority is to measure which prompt spans and
repeated source reads a representation actually replaces. A reversible compact
snapshot alone does not establish a reduction in complete provider usage.

The [revised accelerator plan](https://github.com/endomorphosis/ipfs_accelerate_py/blob/1ec233249317bc4c3772fc4847de27b106eee323/docs/agent_supervisor/reversible_codebase_views_plan.md)
and its [documentation audit](https://github.com/endomorphosis/ipfs_accelerate_py/tree/1ec233249317bc4c3772fc4847de27b106eee323/docs/agent_supervisor/evidence/compact-context-plan-20261012)
are published with accelerator `1ec233249317bc4c3772fc4847de27b106eee323`.

Current unchanged repository views restore exact bytes from retained original
CAS blobs, including after the source checkout is removed. They preserve paths,
names, strings and physical lines. The default Python transform removes trailing
trivia. The actual coding reader covers at most 64 admitted files and 1 MiB;
required source remains inline. Compact edits, a complete editable compact
filesystem and executable identifier/path minification are proposed capabilities,
not delivered behavior. Original-source editing and candidate refresh already
work within their declared scope.

The plan assigns separate roles to IntentIR, CodebaseIR, UI/UX IR, SecurityIR and
LegalIR. Intent requirements select current code/dependency evidence; relevant
capsules, exact source and checked proof statements can then be disclosed in
bounded results. UI/UX semantic and 384D decoder/checkpoint work already exists.
Uniform five-family/fifteen-cell routing needs an additive inventory version;
the original four-family/twelve-cell manifests and existing assets remain valid
historical evidence. Registration and low training loss alone do not establish
semantic reconstruction, formal correctness or provider-token savings.

The proposed implementation and evaluation order is:

1. Extend repository-wide discovery into bounded task-specific read scopes,
   retaining explicit coverage and unsupported frontiers.
2. Add representation-decision receipts binding required coverage, original and
   candidate rendered input, current source/model identities and the actual
   provider-compatible counter. Keep mappings and full indexes host-side;
   retain exact source when counting or coverage is unavailable or a candidate
   is larger. Authenticate the real coding route before changing required
   inline facts.
3. Compare exact and compact reads through the same route with planning and
   provider controls fixed. Count complete planning/coding input and output,
   expansions, retries and repairs once; retain official verifier outcomes and
   cold versus reused setup costs. Future avoided reads require matched runs,
   not a receipt's prediction.
4. Evaluate IR ranking and selected capsules/proof statements as separate
   treatments. Preserve unresolved requirements, currentness and proof
   dependencies; refresh candidates after edits and separately publish accepted
   indexes. Formal JSON can be larger than source.
5. Add a narrow preimage-bound edit mapper only after the read treatment is
   understood. Create/move/delete population changes and executable minification
   need explicit supported operations and their own qualification.

This publication changes documentation only. It performs no new training,
inference, model upload, provider call, solver run or benchmark trial. Existing
