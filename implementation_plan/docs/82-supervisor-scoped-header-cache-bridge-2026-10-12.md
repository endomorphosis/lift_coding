# Scoped native header proof admission to the Doctor cache

The agent supervisor can import a freshly replayed native header lemma into an
existing generic Doctor cache. Its versioned receipt retains the exact local
theorem, assumptions and actual open SecurityIR obligations. Kernel assurance
applies to that lemma; task completion, whole-program proof, mutation and execution
authority remain false. This closes the generic admission gap after the
[native key/custody phase](81-supervisor-header-proof-key-custody-2026-10-12.md).

`LocalProofScope` and `ScopedProofReceipt` use closed schemas; the latter is
`proof-receipt@2`. Standard canonical decoding and cache restart preserve all
conditions. Existing `@1` constructors and canonical identities are unchanged.
The public goal-completion evaluator honors the scoped completion refusal.
Formal-claim, policy, planning, implementation-proof and code-claim/cache-hit
consumers refuse projection that would discard those conditions. Future
scope-aware consumers must specify and verify condition discharge explicitly.

The bridge requires current complete preparation, the existing native Hammer
and sealed SQLite owner, original custody reference, an independently expected
full key, an existing Doctor Gate/cache, and its independently expected canonical
path digest. It checks original source-premise projection/inversion, exact native
requests/outputs/transcripts, reviewed kernel namespaces, actual executable and
implementation bytes, profiles, bounds and original sealed lineage. Fresh native
kernel replay precedes generic evidence creation; HMAC custody or acceptance flags
alone cannot mint assurance. The result is exactly `KERNEL_VERIFIED`, never
`ATTESTED`.

When SecurityIR bindings exist, independent compilation retains genuine generated
obligation IDs as residuals. Native assumptions and open frontier descriptions
remain visible; no assumption or residual obligation is discharged. The receipt
retains original proof/kernel references, stable custody-body identity and current
emitter/codec digests. An identical custody body stored in another row yields the
same generic receipt without equivocation, while the handle still pins its original
row. A later emitter/codec upgrade needs a separately admitted versioned profile/key
migration to avoid correct equivocation under an unchanged key.

Returned key/receipt snapshots are detached and immutable. Accepted/stored values
describe historical admission. Bound render/commit methods recheck current source,
pins, profiles, implementation, original custody/lineage, expected generic receipt,
both owners and durable quarantine/tombstone state. The final combined status read
prevents a newly visible quarantine from being discarded by a tombstone-only
projection. Final source and owner checks follow it. Stage reuse does not rerun
the kernel; reimport after explicit host restart does.

Checks are sequential and grant no atomic lease. Gate bookkeeping may write its
existing owner. A failed final check returns no accepted result, without rolling
back earlier writes. Resource bounds are requested inputs, without certification
of OS enforcement. Receipt byte bounds do not bound native lineage-prefix work or
arbitrary executable effects. The bridge constructs no owner or provider/model.
