## Proposed source and editing lifecycle

1. Inventory the whole admitted public source scope in bounded pages. Retain
   exact source blobs, paths/file kinds/modes and explicit unsupported/excluded
   coverage through existing content stores and metadata owners.
2. Build versioned read-only compact views with source/view digests, retained
   byte-span mappings and hidden-region references. Pass through unsupported
   languages/encodings and binary files. Keep task-relevant explanatory material.
3. Qualify bounded exact-source/capsule access through the actual coding interface
   and existing Quack owner before deferring required source. DuckDB locators and
   DuckLake history do not themselves make content accessible or current.
4. Start with compact navigation and exact-original expansion before normal edits.
   Then evaluate separately versioned mapped edits with explicit original/view
   identities, preimage bytes and replacement bytes. Preserve untouched original
   bytes; stale, hidden-region-crossing or ambiguous edits expand or refuse.
5. Reuse the existing regular-file modify/create materializer within its eight-output
   bound. File moves/deletes and symlink edits require separate native support.
   Validate actual resulting bytes and forward/inverse application; hash strings
   present in a diff are insufficient. Execute ordinary validation on original
   source with accepted edits. Transformed executable source is a separate profile.
6. Qualify mid-coding candidate view/index refresh separately. Existing ranked
   successor refresh requires accepted publication and a completed native task.
   Invalidate changed proof dependencies, retain historical replay and apply the
   existing pinned lineage rules after acceptance.

Unchanged restoration and edited-view materialization are different contracts.
Restoring a baseline snapshot after a compact edit can discard that edit. Source
fidelity, correct execution and token benefit each require their own evidence.
Semantic reconstruction loss cannot certify original source bytes.
