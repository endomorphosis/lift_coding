## `query.py` shard helpers

`country_laws_ir/query.py` `bm25` returns `duckdb_store.bm25_search` when that call does not raise. The helper it reaches is `document_shard_paths`. The exception path calls the helper itself:

```python
        from .duckdb_store import document_shard_paths

        doc_rels = document_shard_paths(self.root, [int(di) for di, _score in ranked])
        if doc_rels is None:
            docs = self._read("data/bm25/documents")
```

`country_laws_ir/duckdb_store.py` defines the helper:

```python
def document_shard_paths(root: Path, document_indexes: list[int]) -> list[str] | None:
    """Document shards for these indexes, or None when the release has no document index."""
```

`bm25_search` calls that helper and, when it returns `None`, reads the DuckDB view `bm25_documents`:

```python
        doc_rels = document_shard_paths(root, [int(row[0]) for row in scored])
        docs_sql = (
            "bm25_documents"
            if doc_rels is None
            else f"read_parquet({_parquet_sql(root, doc_rels)})"
        )
```

That view is bound to the directory `PLAN.md` names:

```python
    ("bm25_documents", "data/bm25/documents/*.parquet"),
```

The document-shard sentences in `PLAN.md` still match these lines. An empty list from `document_shard_paths` is not `None`. `query.py` then builds an empty frame and does not call `_read("data/bm25/documents")`. `bm25_search` returns `[]` when the keyword index exists and selects no posting shards, before it calls `document_shard_paths`.

`query.py` `neighbors` returns `duckdb_store.graph_neighbors` when that call does not raise. The exception path is the direct `adjacency_shard_paths` lookup:

```python
        from .duckdb_store import adjacency_shard_paths

        for d in dirs:
            indexed = adjacency_shard_paths(self.root, node_cid, d)
            if indexed is None:
                path = self.root / "data" / "graph" / "adjacency" / d
                files = sorted(path.glob("*.parquet"))
            else:
                files = [self.root / rel for rel in indexed]
```

`dirs` on that path is `["incoming", "outgoing"]` when `direction` is `"both"`. The glob is `data/graph/adjacency/incoming/*.parquet` or `data/graph/adjacency/outgoing/*.parquet`.

`duckdb_store.py` defines the helper:

```python
def adjacency_shard_paths(root: Path, node_cid: str, direction: str) -> list[str] | None:
    """Adjacency shards whose CID range contains this node, or None when unindexed."""
```

It returns `None` when `indexes/graph_{name}_adjacency.parquet` is not a file. `graph_neighbors` calls the same helper when that index file exists. When the index is missing it does not glob `data/graph/adjacency/*.parquet`. It reads a registered DuckDB view:

```python
VIEWS = (
    ...
    ("graph_in", "data/graph/adjacency/in/*.parquet"),
    ("graph_out", "data/graph/adjacency/out/*.parquet"),
    # Legacy country-laws-ir layout still on some Hub packs.
    ("graph_incoming", "data/graph/adjacency/incoming/*.parquet"),
    ("graph_outgoing", "data/graph/adjacency/outgoing/*.parquet"),
```

## Lines that no longer match `PLAN.md`

`PLAN.md` says adjacency falls back to `data/graph/adjacency/*.parquet` only when the index is `None`.

The `None` condition still matches `query.py` (`indexed is None`) and `graph_neighbors` (the view branch runs when `indexed is None`). The glob does not. No line in these files globs `data/graph/adjacency/*.parquet`. The exception path globs `data/graph/adjacency/<direction>/*.parquet` with `incoming` or `outgoing`. `graph_neighbors` reads the four subdirectory views above (`in`, `out`, `incoming`, `outgoing`).

`PLAN.md` does not mention that `bm25` and `neighbors` return `bm25_search` and `graph_neighbors` before those direct helpers run. The helpers still run inside those functions, and again on the exception paths quoted above.
