## The file that separates public law from US Code consolidation

`ipfs_datasets_py/processors/legal_scrapers/federal_scrapers/public_law_change_processor.py` last changed in `ca0dc4b8e707b3f3f19511606bfbb053b93f93ee`. This is the file that makes the difference. A GovInfo Public Law package is the official change. A House OLRC / `uscode.house.gov` view is a cross-check and cannot replace that package.

The module docstring says:

```text
* House OLRC codification views and eCFR/FederalRegister.gov material may
  appear only as **cross-check** (``unofficial-current`` /
  ``derived_presentation``); they never replace the official GovInfo Public
  Law artifact.
* Official Public Law packages carry ``authority_tier=official-change`` with
  ``IdentityRole.OFFICIAL_ARTIFACT``.
```

```python
SCHEMA_VERSION = "public-law-change-processor-v1"
FIXTURE_SCHEMA_VERSION = "public-law-change-fixture-v1"
```

```python
CROSS_CHECK_PROVIDERS = frozenset(
    {
        "ushouse",
        "uscode.house.gov",
        "house",
        "ecfr",
        "www.ecfr.gov",
        "federalregister.gov",
        "www.federalregister.gov",
        "fr.gov",
    }
)
```

```python
class CrossCheckRole(str, Enum):
    """How a non-GovInfo view is used relative to the official Public Law."""

    NONE = "none"
    HOUSE_CODIFICATION = "house_codification"
    ECFR_PRESENTATION = "ecfr_presentation"
    FEDERAL_REGISTER_DISCOVERY = "federal_register_discovery"
    OTHER = "other"
```

`stable_public_law_identity` returns `plaw:us:{congress}:{law_number}`. `PublicLawRecord.authority_tier` returns `AuthorityTier.OFFICIAL_CHANGE`. `PublicLawRecord.to_dict` writes these keys: `affects_titles`, `authority_tier`, `citation`, `congress`, `content_sha256`, `cross_checks`, `date_approved`, `date_enacted`, `formats`, `law_number`, `metadata`, `notes`, `official_artifact`, `package_id`, `patent_relevant`, `receipt`, `retrieved_at`, `source_spans`, `source_url`, `stable_id`, `status`, `subjects`, `text_excerpt`, `title`, `verification_state`.

`assert_cross_check_only` is the refusal. A provider in `CROSS_CHECK_PROVIDERS`, including `uscode.house.gov`, cannot carry `IdentityRole.OFFICIAL_ARTIFACT` or an official authority tier:

```python
def assert_cross_check_only(
    *,
    provider: Any,
    role: IdentityRole | str | None = None,
    authority_tier: AuthorityTier | str | None = None,
    cross_check_role: CrossCheckRole | str | None = None,
) -> None:
    """Fail closed when a cross-check provider is labeled as official."""
```

Those are two different strings.

## US Code consolidation stays a law schema

`ipfs_datasets_py/processors/legal_scrapers/federal_scrapers/us_code_scraper.py` last changed in `5b60299354522835994ae7076e357f13583ab88c`. The module docstring says it downloads title packages and produces section-level records for full U.S. Code ingestion. It assigns no schema version. `_extract_consolidated_sections` writes a consolidated section dict with keys `section_number`, `heading`, `text`, `body_text`, and `citations`, plus `title_number`, `title_name`, `year`, `package`, and `source_url` when metadata is included. The package default is `USCODE-{year}-title{title}`. The per-HTML section record adds `chapter`, `preamble`, `legislative_history`, `subsections`, and `parser_warnings`. `legislative_history` here is a field parsed out of a code section. It does not make this file a legislative-act schema.

`ipfs_datasets_py/processors/legal_scrapers/federal_scrapers/uscode_release_processor.py` last changed in `e92671688a60a27435d012debceec38a29e49edb`. It acquires U.S. Code release points. The module docstring names the stable section identity ``usc:{title}:{section}``. The function that returns the identity says the shape is ``usc:{jurisdiction}:{title}:{section}`` and returns `usc:{jurisdiction}:{title}:{section}` with the jurisdiction lower-cased. Source format is excluded from that identity.

```python
SCHEMA_VERSION = "uscode-release-processor-v1"
FIXTURE_SCHEMA_VERSION = "uscode-release-fixture-v1"
```

`ipfs_datasets_py/processors/legal_data/uscode_release_schema.py` last changed in `c9e2f8bf44095e65561da83e152a1a20624aa2ff`. This is the release schema for the consolidated US Code corpus, not a public-law or gazette-act schema.

```python
SCHEMA_VERSION: Final = "uscode-sparse-graphrag-release-schema-v2"
RELEASE_PROFILE: Final = "publicus-ir-graphrag/v2"
```

`national_collectors/catalog.py` lists the scraper under `IN_TREE_SCRAPERS` as key `us-uscode`, module `ipfs_datasets_py.processors.legal_scrapers.federal_scrapers.us_code_scraper`, summary `United States Code.` That catalog row is a dataset pointer. It does not assign `gazette_act` or `public-law-change-processor-v1` to the scraper.
