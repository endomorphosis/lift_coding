The only court identity field it reads from a CAP row is the metadata key `court`, listed in `metadata_priority_fields` beside case fields such as `citation`, `case_id`, and `docket_number`. `docket_number` is a case field on that tuple, not a court id.

`build_knowledge_graph_seeds` copies `metadata["court"]` onto the Case node, and, when that value is present, adds an in-memory graph node. The method docstring says this does not construct a full graph database:

```python
court = metadata.get("court")
if court:
    court_id = f"court:{court}"
    nodes[court_id] = {
        "id": court_id,
```

That node has one property, `name`. The id is the string `court:` plus the metadata value. There is no court table, no `court_id` column, and no separate court schema. The Case node remains the opinion-side record.

## Docket sources carry a court reference, not a court table

### `recap_archive_scraper`

Local file: `ipfs_datasets_py/processors/legal_scrapers/recap_archive_scraper.py`, last changed in `df93e91e6338c84a17c3208ef68b88de8566f78c`. The file assigns no schema version and does not write a table.

Search rows identify the court with `court` (from the result field `court`) and `court_full_name` (from `court_name`). They do not store `court_id`. The `court` argument to `search_recap_documents` is a query filter. The docstring examples are `"ca9"` and `"nysd"`. That filter is not a stored court row.

`_hydrate_recap_document_metadata` loads `https://www.courtlistener.com/api/rest/v3/dockets/{docket_id}/`. From the docket object it copies `court_id` and `court`. When `court` is an `http` URL, it fetches that URL and reads `full_name` and `short_name`:

```python
hydrated["court"] = (
    court_data.get("full_name", "") or court_data.get("short_name", "") or court_id
)
hydrated["court_full_name"] = court_data.get("full_name", "") or hydrated["court"]
```

`get_recap_document` then keeps `court` on the document and puts `court_id` and `court_full_name` in `metadata`, beside `docket_number`. `docket_number` identifies a case on the docket, not the court as an institution. The document also has `text` from `plain_text` when text is requested. This module has no court table. The CourtListener court URL is a remote reference, not a local court schema.

### `courtlistener_ingestion`

Docket fetches use `dockets/{docket_id}/` under that root. The returned payload is a docket: `docket_id`, `case_name`, `court`, `documents`, and party lists. Court identity on that payload is:

- `court`, chosen from the first present docket field among `court_id`, `court_name`, `court_full_name`, and `court`
- `metadata["court_id"]` from `court_id`
- `metadata["court_name"]` from `court_name` or `court_full_name`

`_normalize_courtlistener_court_reference` turns a CourtListener court URL into the last path segment:

```python
match = re.search(r"/courts/(?P<court_id>[^/]+)/?$", text)
```

If the value is not such a URL, the function returns the original string. This file does not define a court table and does not store opinion text as a court row. `metadata["docket_number"]` and `metadata["pacer_case_id"]` stay case identifiers.

`upload_world_courts.py`, same commit, publishes `endomorphosis/world_courts`. `flat_court` requires `court_id` and `country_code` and copies these institution fields: `name`, `official_name`, `level`, `court_system`, `subdivision`, `record_type` (default `"courthouse"`), `license`, `geo_source`, `upstream`, `subdivision_method`, `hours`, `email`, `jurisdiction`, `county_fips`, `parent_court_id`, address `street` / `city` / `postcode`, geo `lat` / `lon`, `phone`, `website`, `wikidata`, `place_ids`, `place_match_method`, `source_url`, `source_kind`, `site_policy`, `sources_json`, `needs_review`, `retrieved_at`.

The publisher writes parquet at `data/courthouses/<cc>`. That is the court table this checkout actually builds. It is not an opinion body and it does not reuse `country-laws-ir-graphrag/v1`.

The fields above are the ones this file and `flat_court` actually assign.
